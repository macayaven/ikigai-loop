Of those, 8 got out by design and 2 are findings.

- cal-summary-tag (calendar.event.created.SUMMARY): I count this hand tag as by design: docs/PRIVACY.md says a literal tag in a title counts as a hand tag.
- gh-push-repo, gh-pr-repo, gh-issue-repo, gh-release-repo (github.push.repo, github.pr.repo, github.issue.repo, github.release.repo): I count public repo names as by design: the collector tiers GitHub rows public. With no token the collector reads public events only. A token belonging to the same user would also return that user's private events stamped public, and a token is what would change this line. I run with no token.
- feed-title (feed.item.title): I treat feed text as public by source, and I let it out only as a topic of at most 6 words.
- feed-source, screen-category (feed.item.source, screen.hour.minutes_by_category): I send metric labels out on purpose as metric ids: screen category keys and feed source names go out as metric ids, the collectors' closed tables keep them closed, and my direct rows are a row no real collector writes.

Stopped before any send:
- the repo field on github.push rows (gh-private-repo): the fact layer's leak check dropped it before it became a fact, so it never reached a prompt.
- the entry in my private terms list (deny-term): it became a stored fact, then the outbound scan blocked the prompt carrying it before any send.
The internal-only label reached no outbound channel.

What the findings mean: a local model that misbehaves can copy any digit-free word it sees in its prompt into a fact, because the fact layer checks statements for aliases, digits, whole private values and feed headlines, not against these fields. What it did not see that way: calendar titles and locations, commit text, and window and app titles. The findings are the category field on calendar.event.created rows (cal-category); the counts field on github.push rows (gh-counts-key).
