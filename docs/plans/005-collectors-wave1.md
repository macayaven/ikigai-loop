## Success Criteria

- `framework/collectors/` (pyright strict clean) exposes three collectors implementing the T4 `Collector` protocol: `CalendarIcsCollector` (`name="calendar"`, `version="calendar@0.1.0"`), `GitHubEventsCollector` (`name="github"`, `version="github@0.1.0"`), `BuildFeedCollector` (`name="feed"`, `version="feed@0.1.0"`). Each `Event.source` equals its collector `name`, each `collector_version` equals its `version`. Nothing under `framework/schemas/` or `framework/store/` changes.
- Calendar: reads the iCal URL from env `ICAL_URL` at poll time; that value never appears in logs, stdout/stderr, stored data, cursors, or exception text (proven by test). Window is `[now-2d, now+14d)` on instance start, recurring events expanded via `icalendar` + `recurring-ical-events`. `source_id = "<UID>@<RECURRENCE-ID or start>@<LAST-MODIFIED>"` (exact recipe in Approach). The title is used only to derive `tags` (`iki-[a-z]+` tokens) and `is_new` (`new:` prefix), then dropped — no stored event contains any title text. `busy` comes from `TRANSP`, `category` is always `"personal"`, tier is always `private`. The cursor keeps the last-poll instance snapshot; an instance that disappears emits `calendar.event.cancelled` only while its stored start is still `>= window_start` of the current poll — an instance whose start has aged before `window_start` is dropped from the snapshot silently, with no event (ageing out is not cancellation).
- GitHub: `GET https://api.github.com/users/{GITHUB_USER}/events`, optional `GITHUB_TOKEN`, ETag kept in the cursor (`304` → no events). Events whose repo is `ikigai-loop` are excluded. `PushEvent`/`PullRequestEvent`/`IssuesEvent`/`ReleaseEvent` map to `github.push`/`github.pr`/`github.issue`/`github.release` with the pinned `counts` recipes in Approach; `source_id` is the GitHub event id; tier `public`.
- Build feed: HF daily papers, HN top stories (first 30), GitHub search for repos created in the last 7 days sorted by stars (first 30). Each item is emitted at most once per Europe/Madrid day via the cursor, so same-day score changes never conflict. `source_id = "<source>:<item id>@<YYYY-MM-DD>"` (Madrid date); tier `public`.
- All collectors take `subject_id` from env `IKIGAI_SUBJECT_ID` (default `"subject-1"`, read at poll time). Every HTTP call has a timeout; any network/HTTP error raises out of `poll`, so `run_collector` writes nothing (no events, no cursor move).
- CLI: `python -m framework.collectors run calendar|github|feed` runs one collector via `run_collector` against the default store and prints exactly one line `inserted=<n> conflicts=<n>` — never event content, never a URL.
- `pyproject.toml` gains exactly the two new runtime deps (`icalendar`, `recurring-ical-events`) resolved and pinned by `uv` into `uv.lock`; HTTP stays stdlib. `.env.example` gains empty `ICAL_URL`, `GITHUB_USER`, `GITHUB_TOKEN`, `IKIGAI_SUBJECT_ID` entries (names only, no values).
- Tests are offline only, on synthetic fixtures shaped like each API response: ICS with a recurring event, an `iki-*` `new:` event, and a cancelled-by-disappearance case; title absent from every stored event; GitHub with an `ikigai-loop` event excluded and ETag `304` = no events; feed re-poll the same Madrid day emits 0, next day re-emits; a dedicated test proves `ICAL_URL` never appears in captured logs or exception text. No test opens a socket or reads a real calendar/account.
- `docs/sessions/005-collectors-wave1.md` evidence note (first line of `muse --version` run in the implementation session, models/efforts per phase) and a `CONTRIBUTIONS.md` Ticket 5 entry exist. `make check` is green; exactly one commit on `t5-collectors-wave1`, not pushed.

## Approach

Key decisions (all binding on the implementer; alternatives are rejected in Risks only where the choice was live):

- **Package layout is exactly six modules.** `framework/collectors/__init__.py` (docstring + re-exports + `__all__`), `framework/collectors/common.py` (shared env/clock/HTTP/event helpers below), `framework/collectors/calendar_ics.py` (`CalendarIcsCollector`), `framework/collectors/github_events.py` (`GitHubEventsCollector`), `framework/collectors/build_feed.py` (`BuildFeedCollector`), `framework/collectors/__main__.py` (CLI). One module per collector as the ticket requires; `common.py` is the only shared module. No other collectors modules; no async; no change to `framework/schemas/` or `framework/store/`.
- **Schemas and store are used as-is.** Import `Event` and the payload models from `framework.schemas` (`CalendarEventCreatedData`, `CalendarEventUpdatedData`, `CalendarEventCancelledData`, `GitHubPushData`, `GitHubPrData`, `GitHubIssueData`, `GitHubReleaseData`, `FeedItemData`). Import `Collector` (for typing only), `run_collector`, and `EventStore` from `framework.store`. Never edit anything under `framework/schemas/`, `schemas/`, or `framework/store/`. Calendar payloads structurally cannot carry a title (`extra="forbid"`, no `title` field) — the collector must simply never pass one.
- **HTTP is stdlib `urllib.request`, not `httpx`.** Justification: the ticket adds exactly two parsing deps (`icalendar`, `recurring-ical-events`); `urllib` covers the four GET endpoints here (one iCal fetch, GitHub events, GitHub search, HF, HN) with headers, ETag, and status handling, and keeps `uv.lock` churn to the calendar stack. `httpx` would be a third new runtime dep for no behaviour these collectors need. The test seam is an injected callable (below), so no test ever touches `urllib` or a socket. Add the deps with `uv add icalendar recurring-ical-events` and let `uv` resolve versions compatible with Python 3.12; commit both `pyproject.toml` and `uv.lock`; invent no version numbers in code or docs.
- **The HTTP seam is one injected callable, shared by all three collectors** (in `common.py`, pyright-strict typed; `Any` is allowed only for the opaque cursor, as in T4):

```python
@dataclass(frozen=True)
class HttpResponse:
    status: int
    headers: dict[str, str]  # keys lower-cased by the producer
    body: bytes


HttpGet = Callable[[str, dict[str, str]], HttpResponse]


class CollectorError(Exception):
    """A poll failure. Messages never contain a URL, a header value, or a response body."""
```

  The default producer `urllib_http_get(url: str, headers: dict[str, str]) -> HttpResponse` builds a `urllib.request.Request`, calls `urllib.request.urlopen(request, timeout=15.0)` (15 s on every call, no exceptions), lower-cases response header keys, and returns the body bytes. `urllib.error.HTTPError` is **not** an error here: it is converted to an `HttpResponse` with that status/headers/body so callers can handle `304`/404 themselves. `urllib.error.URLError`, `OSError`, and `TimeoutError` become `raise CollectorError("<collector>: network error") from None` — the `from None` and the URL-free message are mandatory (see the `ICAL_URL` rule). Collectors raise `CollectorError` themselves for bad statuses with messages of the exact form `"<collector>: fetch failed (status <n>)"` and for unparseable bodies as `"<collector>: invalid response"` — never interpolating the URL, headers, or body. Each collector constructor accepts `http_get: HttpGet = urllib_http_get`; tests always inject a fake.
- **Clock and env are injected/read the same way everywhere.** Each collector constructor accepts `now_fn: Callable[[], datetime]` defaulting to `lambda: datetime.now(UTC)`; `poll` calls it once and uses that single instant as `collected_at` for every event in the poll (and as `now` for windows/dates). All env reads happen at the start of `poll`, never at import or construction, so tests can `monkeypatch.setenv` then construct or construct then set env: `subject_id` via the `common.py` helper `subject_id_from_env() -> str` returning `os.environ.get("IKIGAI_SUBJECT_ID") or "subject-1"`; `ICAL_URL` and `GITHUB_USER`/`GITHUB_TOKEN` read inside their own collector's `poll`. Missing required env raises `CollectorError("calendar: ICAL_URL is not set")` / `CollectorError("github: GITHUB_USER is not set")` — the message names the variable, never a value.
- **Event ids are deterministic.** `common.event_id(source: str, source_id: str) -> str` returns `"evt_" + hashlib.sha256(f"{source}\x00{source_id}".encode()).hexdigest()[:32]`. PLAN §2.2 shows a ULID example, but T3 made `id` an opaque string with no format check and T4's store ignores `id`/`collected_at`/`collector_version` for identity; a deterministic hash id keeps collectors replayable (PLAN D5: deterministic, replayable) and tests exact. No `ulid` dependency.
- **Emission order is deterministic.** Every collector sorts or preserves a pinned order before returning (per-collector rule below), because `run_collector` inserts in poll order and tests compare exact event lists.
- **A network error raises and `run_collector` writes nothing** is inherited, not re-implemented: `run_collector` (T4) calls `poll` outside any transaction, so any `CollectorError` (or parse `ValueError`) escaping `poll` leaves events and cursor untouched. Collectors must therefore do **all** fetching and parsing before returning, and must never catch-and-return-partial on a fetch failure. The one exception is per-item skips for malformed entries inside an otherwise successful response (pinned per collector below) — a skipped item is not a failed poll.
- **Calendar (`calendar_ics.py`, `CalendarIcsCollector`, `name="calendar"`, `version="calendar@0.1.0"`).**
  - Fetch: `url = os.environ.get("ICAL_URL")`; missing/empty → `CollectorError("calendar: ICAL_URL is not set")`. `response = http_get(url, {})`; `status != 200` → `CollectorError(f"calendar: fetch failed (status {response.status})")`. The URL is held only in a local variable: never stored on `self`, never put in the cursor, never logged, never formatted into any exception (including chained ones — always `from None`). The class defines no `__repr__` carrying state.
  - Parse/expand: `cal = icalendar.Calendar.from_ical(response.body)` (a parse failure → `CollectorError("calendar: invalid response") from None`); `window_start = now - timedelta(days=2)`, `window_end = now + timedelta(days=14)`; `components = recurring_ical_events.of(cal).between(window_start, window_end)`, then keep only instances with `window_start <= start < window_end` (half-open on start). `now` is the poll instant from `now_fn`.
  - Per instance (a `VEVENT` component): `uid = str(component.get("UID", ""))` and `start` from `component.decoded("DTSTART")`; skip the instance silently if either is missing. Normalise every datetime with one helper: a `date` (all-day) becomes midnight `Europe/Madrid`; a naive `datetime` gets `ZoneInfo("Europe/Madrid")` attached; an aware one is kept, and ISO strings are produced as `value.astimezone(UTC).isoformat()`. `end`: `component.decoded("DTEND")` if present, else `start + component.decoded("DURATION")` if present, else `start`.
  - Keys: `instance_key = f"{uid}@{rid}"` where `rid` is the UTC-ISO of `RECURRENCE-ID` (`component.decoded("RECURRENCE-ID")`) when present, else the UTC-ISO of `start`. `last_modified` is the UTC-ISO of `LAST-MODIFIED` when present, else `f"seq{seq}"` when `SEQUENCE` is present (`seq` = `int(component.decoded("SEQUENCE"))`), else `"seq0"`. `DTSTAMP` is never read for this (or any) purpose: Google sets it to feed generation time, so it changes on every fetch and would mint a new `source_id` — and a spurious `updated` — per poll. `source_id = f"{instance_key}@{last_modified}"` — the ticket's `"<UID>@<RECURRENCE-ID or start>@<LAST-MODIFIED>"` with the `SEQUENCE` fallback above.
  - Title handling (derive, then drop): `summary = str(component.get("SUMMARY", ""))`; `tags` = `re.findall(r"iki-[a-z]+", summary)` deduplicated preserving first-seen order; `is_new = summary.strip().startswith("new:")` (case-sensitive). `summary` is a local only: never stored, logged, or interpolated anywhere. `busy = str(component.get("TRANSP", "OPAQUE")).upper() != "TRANSPARENT"`. `category = "personal"`. Tier `"private"`. Envelope `time` = instance `start`.
  - Cursor (JSON object; `None` → `{"instances": {}}`): `{"instances": {instance_key: {"source_id": str, "start": iso, "end": iso, "busy": bool, "tags": [...], "is_new": bool}}}` — the last-poll snapshot, which is what makes cancelled events constructible. Poll algorithm: build `current: dict[instance_key, snapshot]` from the expanded instances; `prev` = cursor's `instances` (or `{}`). For each key in `current`: absent from `prev` → emit `calendar.event.created`; present with a different `source_id` → emit `calendar.event.updated`; present with the same `source_id` → emit nothing (an upstream change bumps `LAST-MODIFIED`, hence `source_id`; re-emitting identical content would only risk a conflict). For each key in `prev` absent from `current`: if the stored snapshot's `start` instant is still `>= window_start` of this poll, emit `calendar.event.cancelled` built from the stored snapshot (`start`/`end`/`busy`/`tags`/`is_new`, `category="personal"`), with `time` = stored `start` and `source_id = f"{prev_source_id}#cancelled"` (distinct from the created/updated key, so the append-only store accepts it; a second disappearance of the same `LAST-MODIFIED` version is then an identical re-delivery and a store no-op — accepted, see Risks); if the stored `start` is `< window_start`, emit nothing — the instance has aged out of the sliding `[now-2d, now+14d)` window, which is not a cancellation. Either way the key leaves the snapshot: new cursor = `{"instances": current}`. Emitted events sorted by `(time, source_id)`.
- **GitHub (`github_events.py`, `GitHubEventsCollector`, `name="github"`, `version="github@0.1.0"`).**
  - Fetch: `user = os.environ.get("GITHUB_USER")`; missing/empty → `CollectorError("github: GITHUB_USER is not set")`. URL is exactly `f"https://api.github.com/users/{user}/events?per_page=100"` (one page, no pagination — see Risks). Headers: `{"Accept": "application/vnd.github+json", "User-Agent": "ikigai-loop"}`, plus `"If-None-Match": <etag>` when the cursor holds one, plus `"Authorization": f"Bearer {token}"` only when `GITHUB_TOKEN` is set non-empty (the token, like `ICAL_URL`, never appears in any message or log). `status == 304` → return `([], cursor)` with the cursor unchanged. `status != 200` → `CollectorError(f"github: fetch failed (status {status})")`. Body must decode as a JSON list, else `CollectorError("github: invalid response") from None`.
  - Cursor: `{"etag": str | None}` (`None` cursor → `{"etag": None}`). On `200`, the new etag is the response's lower-cased `etag` header when present, else the previous etag.
  - Mapping (API order preserved; skip silently any entry that is not a dict, lacks `id` or `repo.name`, or has an unlisted `type`): exclude first when `repo_name.rsplit("/", 1)[-1] == "ikigai-loop"` (so any owner's `ikigai-loop` is excluded, per PLAN D4). `repo` = full `repo.name` (e.g. `"synthetic/repo"`). `time` = `created_at` parsed with `datetime.fromisoformat(value.replace("Z", "+00:00"))`. `source_id = str(entry["id"])`. Tier `"public"`. Counts, exactly: `PushEvent` → `github.push`, `{"commits": payload["size"] if isinstance(payload.get("size"), int) else len(payload.get("commits") or [])}`; `PullRequestEvent` → `github.pr`, `{"merged": 1}` when `action == "closed"` and `(payload.get("pull_request") or {}).get("merged") is True`, else `{action: 1}`; `IssuesEvent` → `github.issue`, `{action: 1}`; `ReleaseEvent` → `github.release`, `{action: 1}` — where `action = str(payload.get("action") or "unknown")` and `payload = entry.get("payload") or {}`.
- **Build feed (`build_feed.py`, `BuildFeedCollector`, `name="feed"`, `version="feed@0.1.0"`).** Envelope `source="feed"`; `FeedItemData.source` is one of `"hf"`, `"hn"`, `"github"`; tier `"public"`; envelope `time` = the poll instant for every item. One `Madrid` constant `ZoneInfo("Europe/Madrid")` local to this module; `today = now.astimezone(MADRID).date().isoformat()`.
  - Sub-sources, fetched in this order, events emitted in this order (API order within each): (1) HF: `GET https://huggingface.co/api/daily_papers` (no auth headers); body is a JSON list; per entry, `paper = entry.get("paper") or {}`, skip when `paper` lacks `id` or `title`; item id `str(paper["id"])`, `title=str(paper["title"])`, `url=f"https://huggingface.co/papers/{paper['id']}"`, `score=float(paper.get("upvotes") or 0)`. (2) HN: `GET https://hacker-news.firebaseio.com/v0/topstories.json` → JSON list of ids, take the first 30; per id `GET https://hacker-news.firebaseio.com/v0/item/{id}.json`; skip a `null`/non-dict item or one with `deleted`/`dead` true or no `title`; `title=str(item["title"])`, `url=str(item.get("url") or f"https://news.ycombinator.com/item?id={id}")`, `score=float(item.get("score") or 0)`, item id `str(id)`. (3) GitHub search: `since = (Madrid today − 7 days).isoformat()`; URL built with `urllib.parse.urlencode` as `https://api.github.com/search/repositories?q=created:>={since}&sort=stars&order=desc&per_page=30`, same `Accept`/`User-Agent` headers as the GitHub collector plus `Authorization` when `GITHUB_TOKEN` is set; body JSON object, `items = body.get("items") or []`, take the first 30; skip entries lacking `id`, `full_name`, or `html_url`; `title=str(repo["full_name"])`, `url=str(repo["html_url"])`, `score=float(repo.get("stargazers_count") or 0)`, item id `str(repo["id"])`. Any non-`200` from any sub-source, or an undecodable body, raises `CollectorError(f"feed: fetch failed (status {status})")` / `CollectorError("feed: invalid response") from None` and fails the whole poll (nothing partial). A `float(...)` conversion failure skips that item.
  - Once-per-Madrid-day rule: cursor `{"day": "YYYY-MM-DD", "emitted": ["<source>:<item id>", ...]}` (`None` → `{"day": today, "emitted": []}`; a cursor whose `day != today` starts from an empty emitted set). For each candidate in order, `key = f"{data_source}:{item_id}"`; skip when `key` is already emitted today; otherwise emit with `source_id = f"{key}@{today}"` (exactly the ticket's `"<source>:<item id>@<YYYY-MM-DD>"`) and add `key`. New cursor = `{"day": today, "emitted": sorted(previous_today_keys ∪ new_keys)}`. Because a same-day re-poll emits nothing, a score change that day can never reach the store as a conflict; the next Madrid day re-emits under a new `source_id`.
- **CLI (`__main__.py`).** `main(argv: list[str] | None = None, *, http_get: HttpGet = urllib_http_get, now_fn: Callable[[], datetime] | None = None, db_path: Path | None = None) -> int` (the keyword seams exist for tests; the real entry point passes none of them). `argparse` with a required `run` subcommand and `name` restricted to `choices=["calendar", "github", "feed"]`. It builds the matching collector (passing `http_get`, and `now_fn` when given), opens `EventStore(db_path)` as a context manager, calls `run_collector`, prints exactly `inserted=<n> conflicts=<n>` (one line, stdout), and returns `0`. A `CollectorError` is caught: print `error: <message>` to stderr and return `1` (messages are URL-free by construction). Any other exception propagates. `if __name__ == "__main__": raise SystemExit(main())`, so `python -m framework.collectors run <name>` works; an unknown name is an argparse error (exit 2). The CLI never prints events, titles, URLs, or env values. `build_collector(name: str, http_get: HttpGet, now_fn: ...) -> Collector` is a module-level helper the CLI tests can call directly.
- **pyright strict and style.** `framework/` is strict: annotate every function (including `-> None`), no untyped defs, no bare `dict`/`list` without parameters where the value type is known (cursor values are the one sanctioned `Any`, matching T4). Follow the neighbouring style in `framework/schemas/` and `framework/store/` (short module docstrings, double quotes, ruff format). Tests live in `tests/` (standard mode) but are still annotated `-> None` like the T3/T4 tests.
- **Fixtures are synthetic only.** The committed ICS fixture and the inline JSON fixtures use invented UIDs, titles, repos, and paper/item ids (e.g. `synthetic/repo`, `iki-partner` as a tag token, never a person). The fake `ICAL_URL` in tests is `https://example.invalid/secret-calendar-token.ics` — obviously synthetic, `.invalid` TLD, no real host or credential. No fixture contains a real calendar, account, name, or token.

## Risks

- **`ICAL_URL` leaking through an exception chain, log, or repr.** The URL is a credential. Mitigated by construction: held only in a `poll` local, every raise uses `from None` with a URL-free pinned message, `urllib` errors are converted in `common.py` without interpolating the request, nothing logs at all in `framework/collectors/`, and AT5 asserts the secret string appears in neither exception text nor `caplog` on the success, HTTP-error, and network-error paths. Gitleaks in `make check` covers the committed tree (the test value is `.invalid` and synthetic regardless).
- **Recurring expansion differing across `recurring-ical-events` versions.** The lib's `of(cal).between(a, b)` boundary behaviour is version-dependent, so the plan pins a second, explicit half-open filter on instance start (`window_start <= start < window_end`) after expansion; AT1's fixture arithmetic is computed against that filter, not the library's edges. `uv.lock` pins whatever `uv add` resolved.
- **A changed calendar event emitting a conflict instead of an update.** If neither `LAST-MODIFIED` nor `SEQUENCE` changed, `source_id` is unchanged and the collector emits nothing (Approach), so silent upstream edits without either bump are missed until one lands — accepted: iCalendar producers bump `LAST-MODIFIED` (or `SEQUENCE`) on edit, and the alternative (re-emitting under the same `source_id`) would record append-only conflicts on every poll. `DTSTAMP` is deliberately never used as the change signal: Google rewrites it to feed generation time on every fetch, so keying on it would emit a spurious `updated` for every instance on every poll (AT3c proves a `DTSTAMP`-only change emits nothing).
- **Cancelled-then-reappearing instance.** A reappearing instance key emits `created` again under its (possibly new) `source_id`; a second disappearance of the same `LAST-MODIFIED` version reuses the `#cancelled` `source_id` and is a store no-op. Accepted for wave 1: the event stream still shows the first cancellation, and per-disappearance unique keys would need a poll counter in the cursor for no signal gain at n=1.
- **GitHub events API limits.** One `per_page=100` page, no pagination: the API only retains 300 events / 90 days and polling is frequent, so one page is enough; a very busy day could drop older same-day events off the page. Accepted for wave 1 (noted here so review sees it); cursor-based pagination is a later ticket if the stream shows gaps. Unauthenticated GitHub search in the feed is rate-limited (10/min) — one search per poll is far under it, and `GITHUB_TOKEN` is honoured when present.
- **HN fan-out cost.** First-30 means 31 HN requests per feed poll (list + 30 items) plus HF and GitHub search. All have the 15 s timeout and any failure fails the poll atomically (AT10), so a slow HN cannot half-write a poll; poll cadence is set by ops (T13), not this ticket.
- **Madrid-day boundary for the feed.** Using UTC dates would re-emit at 01:00/02:00 local. Mitigated by computing `today` with `ZoneInfo("Europe/Madrid")` and AT9 advancing the frozen clock across a Madrid midnight (not a UTC one).
- **Fixture ICS arithmetic drifting from the frozen clock.** The ICS fixture uses absolute `DTSTART`/`RRULE` values, so its expected occurrence count is fixed only relative to the tests' frozen `NOW`. Test Plan pins both, and AT1 counts occurrences by the pinned half-open rule, so a library upgrade that changes expansion edges fails loudly instead of silently changing counts.
