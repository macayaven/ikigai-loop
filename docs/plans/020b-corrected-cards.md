## Risks

- **Chain read loops.** A `replaces_card_id` chain with a cycle could loop. I walk it with a seen set and stop at a repeat, as `chain_groups` does at [framework/cycle/card_build.py](../../framework/cycle/card_build.py:161). A card whose chain never reaches a delivered card of the slot is not delivered.
- **Card claim rule drift.** My restated claim rule can drift from `build_statements` at [framework/cycle/card_build.py](../../framework/cycle/card_build.py:59). The own-rows tests pin both directions, built from the later row and from the earlier row, so a drift fails loudly.
- **Fallback rows with no briefing.** A fallback row may hold no briefing claims. Then no row of that profile qualifies under K2 and I take the latest row, as today. I state this so it reads as a choice, not a gap.
- **Voice table shape drift.** `voice_notes` gains columns over time, as `ensure_voice_columns` at [framework/telegram/ledger.py](../../framework/telegram/ledger.py:76) shows. I select five named columns and treat a missing one as `unknown`, so a new column changes nothing and a dropped one fails closed.
- **Time shape.** `total_s` is a float column at [framework/telegram/ledger.py](../../framework/telegram/ledger.py:53). A stored text or null reads as `unknown`, never as 0.
