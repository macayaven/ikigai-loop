## Approach

### Key decisions (binding on the implementer; each with its reason)

- **D1, two stages, and Stage 1 touches no file under `framework/`.** Stage 1 is the runner, its tests, and the first results on the unfixed gate. The reviewer then writes the adjudication by hand. Stage 2 is the fixes. Reason: a gate change made before the frozen run would destroy the measurement, and an adjudication written after fixes would grade the fix, not the hole.
- **D2, the attack table in this plan pre-assigns a fix class, a closing rule and the full expected code list to every one of the 34 attacks, conditional on the verdict.** The table is section "Attack table". A row's rule falls away if the reviewer rules that row `not_false` or `disclosed_limit`: no mutant is added for that attack and its wording is not special-cased. A shared class rule survives only while at least one `real_hole` row in that class remains. Rows marked "no fix candidate" have no rule even if pressed: they are written up as limits, and if the reviewer insists one is a `real_hole` that is a blocker returned to the reviewer, not an implementer improvisation. Reason: the reviewer asked for the fix classes planned now, before any verdict exists, with fallback clarity per row. The table gives the full ordered code list the fixed gate is expected to return for the runner-context claim, not only the primary code. Those full lists are predictions: in Stage 2 the row's primary code must fire, but if the actual full list differs that is not a stop. The briefing-case mutant pins the actual list, and the session note names every difference. Every other round-1 row apart from A20 (`not_false`) and A25 (`disclosed_limit`) is planned as `real_hole`, with A18 now ruled `real_hole` (D8, attack table); the verdicts are final only once the reviewer's adjudication file exists, and the counts in D20 come from that file.
- **D3, frozen versus current results, stamps, and round-2 reproduction.** Per input file `X` (a round file `round-N.json` or a true-sentences file `true-sentences-*.json`): `X`'s frozen file (`docs/redteam/round-N.frozen.json`, resp. `docs/redteam/true-sentences-<name>.frozen.json`) is written once, in Stage 1 (round 1 and the three blind files) or at round-2 intake, by an explicit `--write-frozen` invocation on the gate as it then stands. It carries `gate_commit` (`git rev-parse HEAD`), `gate_tree` (`git rev-parse HEAD^{tree}`), `gate_files_sha256` and `gate_dirty` (below), the SHA-256 of the input file, and the rows. The default command never writes it, and no later command overwrites it; a test asserts it parses, its ids equal the input file's ids in order, and its stamps are present. The current file (`round-N.results.json`, resp. `true-sentences-<name>.results.json`) is regenerated by every default run and tested for staleness by regenerating to a temp path and diffing. `--summary` reads frozen, current and adjudication files (D17). `gate_files_sha256` is the SHA-256 over the sorted `framework/briefing/*.py` paths and contents: for each path in sorted order, hash the UTF-8 path, a NUL byte, the file bytes, and a NUL byte; `gate_dirty` is true iff `git status --porcelain -- framework/briefing/` is non-empty. Reason for the extra stamps: `gate_commit`/`gate_tree` alone are not enough for round 2, because no commit exists then — HEAD is still the base and the tree is dirty, so a commit-only stamp would claim the base gate. Round-2 reproduction: there is no `docs/redteam/round-2.fixes.patch`, and none will be produced. The gate round 2 attacked was a draft that was discarded and rewritten from prose rules, so it cannot be rebuilt from this repository; its `gate_files_sha256` stays in `docs/redteam/round-2.frozen.json` as the record of what was attacked. Steps 10 and 11 say so where they named the patch, and AT6's reverse-apply check is skipped, with the session note saying so. Because this ticket lands as one commit, a reader likewise reproduces the frozen round-1 file from the base commit named in its `gate_commit`: check that commit out in a separate worktree, run the Stage 1 command there, and the rows match; only the stamp fields can differ if the checkout is not the recorded commit. Reason: "regenerated and tested for staleness" and "kept as they were" cannot both hold for one file once the gate changes, so they hold for two files.
- **D4, one public normalisation function, `normalize_text`, in new `framework/briefing/normalize.py`, re-exported from [framework/briefing/__init__.py](../../framework/briefing/__init__.py); it preserves case, and every comparison casefolds the result.** Ticket 17a imports it, so the name and module are pinned here. Signature: `normalize_text(text: str) -> str`. It returns the checked copy only; it never mutates input and the gate never writes it back, so what Carlos reads is the original text and what was checked is the normalised copy, except where D5 rejects outright on claims. Steps, in order: (1) `unicodedata.normalize("NFKC", text)`; (2) translate the pinned cross-script confusables in D10 to Latin; (3) convert every character with a Unicode digit value (category `Nd`, including full-width and Arabic-Indic digits) to its ASCII digit string; (4) remove the unsafe characters listed in D5 (rejection on claims is decided first, in D5; removal here is what makes matching in `text_check_codes` safe); (5) map curly apostrophes and quotes to straight ones (the existing advice behaviour at [gate.py:145](../../framework/briefing/gate.py:145)), hyphen variants U+2010 to U+2015 and U+2212 to `-`, non-breaking and other Unicode spaces to a plain space; (6) remove combining marks: decompose (`NFKD`), drop every character of category `Mn`, recompose (`NFC`), so "Quíllon" and a word overstruck with combining marks read as their base letters on the checked copy — this closes the accent gap D10 previously left — plus translate the pinned small map of Latin lookalikes that do not decompose: `ı` (U+0131, dotless i) to `i`, `ł`/`Ł` (U+0142/U+0141) to `l`/`L`, `ø`/`Ø` (U+00F8/U+00D8) to `o`/`O`, `đ`/`Đ` (U+0111/U+0110) to `d`/`D`; (7) collapse whitespace runs to one space and strip. There is deliberately no casefold step: `_MONTH_DATE_RE` at [numbers.py:52](../../framework/briefing/numbers.py:52) matches month names only capitalised (comment at [numbers.py:31](../../framework/briefing/numbers.py:31); pinned at [tests/test_briefing_numbers.py:168](../../tests/test_briefing_numbers.py:168)), so a casefolded "Planned for May 9" would stop masking the date and yield `(9,)` with `L1B_NUMBER_WITHOUT_METRIC_REF` on G9 — and the Roman-numeral rule in D8 needs case as well. Every comparison (direction, period, language, advice, label, vocabulary, private-term and raw-literal matching) therefore calls `.casefold()` on the `normalize_text` result, and on pinned list entries likewise, instead of the normaliser folding case. The function is idempotent, with a test: `normalize_text(normalize_text(x)) == normalize_text(x)` over a pinned corpus including full-width, vulgar fractions, combining sequences (precomposed and decomposed forms of the same word giving the same output), the four Latin lookalikes, and mixed digits. Callers pass raw text: every rule normalises for itself by calling `normalize_text` internally, so passing already-normalised text is safe by idempotence and no caller is required to pre-normalise. Reason: one function, used before every text rule, is the only way the rules cannot drift apart; internal normalisation keeps `text_check_codes`' existing signature and meaning for its other callers (D6); case preservation keeps the numbers module's one deliberate case-sensitive mask working.
- **D5, unsafe characters reject on claims only; `text_check_codes` strips them for matching and never returns `L1_UNSAFE_TEXT`.** New code `L1_UNSAFE_TEXT` lives on the claim path only (in `claim_text_codes`, D6), not in `text_check_codes`. What counts as unsafe, checked on the original claim text: any character of category `Cf`; any of `Cc` except tab, newline and carriage return; `Co`; `Cs`; `Cn`; `Me`; and the default-ignorable and blank-rendering characters outside `Cf`: U+034F, U+115F, U+1160, U+17B4, U+17B5, U+180B to U+180F, U+2800, U+3164, U+FFA0, U+FE00 to U+FE0F, U+E0100 to U+E01EF. The bidi and zero-width cases U+202A to U+202E, U+2066 to U+2069, U+200E, U+200F, U+061C, U+200B to U+200D and U+FEFF are all `Cf` and are pinned by code point in the test corpus so the widening cannot silently narrow. Reason, following the reviewer: Ticket 11's outbound scan treats a `text_check_codes` hit as "blocked, noop", so one soft hyphen in a fact statement quoted from a web title would lose the slot, and a commitment title carrying one would fail the whole commitments file at [commitments.py:97](../../framework/briefing/commitments.py:97); actions are already compared to titles exactly at [gate.py:466](../../framework/briefing/gate.py:466), so nothing is gained by rejecting there. What is stripped is safe to strip for matching in `text_check_codes` (D4 step 4 removes these characters on the checked copy, so a spaced or struck-through private term still matches); what is rejected is rejected only on claims, because that is text the model wrote and Carlos reads, and U+202E makes "llef" render as "fell" and "01" render as "10", so a stripped checked copy can differ from what is displayed — fail closed there instead. For everything else where NFKC changes how a character reads (full-width letters, vulgar fractions, ligatures, superscripts, Roman numeral forms): checks run on the NFKC copy, the original is what is stored, and rejection, when a rule fires, is the safe outcome; when no rule fires the text is inert prose and the limit is named in Risks.

"Pushes to seven-tower were 0 in last." citing only the metric stays blocked: nothing evidences the name, and that stays a named limit, along with `3D` in a category or tag name, as the [numbers.py](../../framework/briefing/numbers.py) header already says. A bare number word or digit in a statement masks nothing, so "Five feed items…" is not freed by a statement that says "Five". This closes finding R2; that row's adjudication entry uses `extra_facts` with exactly the evidencing statement, and its known-good case carries a case-local fact.
- **D23, float noise (R4).** In `_ref_backs_token` a token with no decimal places is backed when the value, rounded half-up to 2 places, equals the token. Still failing: 5 for 4.75 (A18), 5 for 4.9999999, 2 for 1.75, and 17 for 17.5. `since_last` behaviour is unchanged and the D15 guard stays. Reason: a live draft wrote the true sentence and the Stage 2 integral rule rejected it over float noise.
- **D24, `held` before a count (R5).** `held` directly before a digit or a spelled number word is containment, not a direction word. One small public helper (`without_count_held` in `claim_text.py`) blanks it there, applied everywhere direction words are read from a claim or a cited statement, on the metric path and the fact arm. Reason: Ticket 10 pins "Feeds held 9" as good, and the same-direction list added in Stage 2 blocked it.
- **D25, phrasal particles on the fact arm (R6).** In `fact_claim_codes` and when reading a cited statement's direction, the closed list (lined up, showed/show/s/showing up, took/take/s/ing up, set/wrote/wrapped/followed up, follow up, wrote/sat down) is removed from the normalised casefolded copy before direction words are read. Fact arm only: the metric path keeps `up` and `down` exactly as they are. Reason: a live draft wrote the true sentence over a directionless fact and the particle `up` failed it closed.
- **D26, `ahead` in a phrase (R7).** Before the rank check in `find_unverifiable_quantities`, the phrases (plan/plans/planned/planning, look/looking, think/thinking ahead) are removed from the copy it reads. A23's "ranked first … ahead of earlier and prior" and "ahead of prior" still fire. Reason: "plan ahead" ranks nothing, and a live draft wrote that shape truly.
- **D27, a value beside its period is checked against that period; positional lists stay out.** `_value_period_hit` runs three passes over the claim: value-then-period ("3 in earlier", with one label or hour word and `in`/`during`/`for` allowed between), period-then-value ("last were 0"), and period-comma-value. Each pair fires `L1B_VALUE_PERIOD_MISMATCH` only when no cited ref of that same period backs the token. A value that runs on into `and` or a comma plus another value is a positional list and is skipped in the backward and comma passes. The fully positional form ("Pushes in prior and last were 0 and 1") stays passing under Limit 2. Reason: beside its period a number reads as that period's number, and I have what I need to check it; a bare ordering of numbers is not such a reading.
- **D28, each clause binds its own value.** The same check splits the claim on commas, semicolons, colons and clause words; a clause holding exactly one period word and exactly one value is tested as that pair alone. Beside it, the gate's binding check stays coarse: a single-ref claim names its metric and period, a multi-ref claim must be one 2 or 3 ref comparison family naming every cited period, and a period word with no cited ref behind it fires. Reason: the clause is the unit a reader binds, and the gate keeps the family shape honest.
- **D29, a stated change equals a difference.** Every pairwise absolute difference of the cited values is computed, and a "difference of X", "change of X", "by X" or "net X" value must be backed by one of those differences or the claim fails. Reason: a named change is a number about the numbers, so it is checked against them.
- **D30, a comparison reads the periods it names.** With exactly two refs in two different periods and one sentence naming period A, then "than", then period B, "higher in prior than in last" passes only when prior's value is above last's: naming order decides, not time order. Any other shape falls back to time order, where every pairwise step must point the same way. Only 2 or 3 refs of one family with distinct periods count as a comparison at all. Reason: "than" points at the words around it, and the P21 fixture is written to that reading now.
- **D31, the bare word one.** A standalone "one" counts as the value 1 only where a count belongs: never after a determiner and never hyphen-joined, and only at the end of the text, before `in`, `during`, `for`, `at`, `and`, `or`, `but`, `across`, `over`, `than`, `to`, `from`, or before punctuation. It enters the value-period check as an exact 1. Reason: "one" is usually prose, and these are the seats where it reads as a number.
- **D32, what may follow a number is a closed list, and an unlisted noun fails the claim.** After a number token may come the allowed followers (comparatives, period words, `total`, `respectively`, plain prepositions and the like), a label word of a cited metric, or the unit nouns of the cited unit class (`hour` words on hours claims, `push`-family and count nouns on count claims). Anything else — a magnitude word, `percent`, a day or week word, or an unlisted noun — fires `L1B_UNIT_MISMATCH`. Its cost is a retry that can end on the fallback card, which is why the list is closed with care rather than open by default. Reason: a number with the wrong noun beside it is not the cited number.
- **D33, joined labels read cited-first.** The cited metrics' own labels are read before anything else, so a cited label holding another metric's label as one of its words ("Video Calls" holding "Video") does not count as naming the other metric. Only a standalone mention outside every cited span fires `L1B_METRIC_LABEL_MISMATCH`, on the raw and the camel-split copy alike. Reason: real labels contain each other, and the check must not punish the cited label for that.
- **D34, the text cap.** Any section text over 2000 characters gets `L1_TEXT_TOO_LONG` and is skipped for further text checks; an over-long claim is skipped silently on the claim sweep, since the section hit already fired. Reason: past that length the text is not a claim I can check line by line.
- **D35, floats compare exact.** A ref value is compared to the snapshot value as exact decimals of their shortest printed forms, with no epsilon; any ref at or above 2 to the 53rd is an automatic mismatch, since two integers up there can share one float. Reason: near enough is not cited, and up there equality itself is unreadable.
- **D36, glued forms, qualifiers and quantity words.** Letter-digit adjacency only fires on `x` forms (`2x`, `x3`); other glued runs (`steps9065`) fire unless the tail belongs to another rule (`9h`, clock times, `3rd`, `am`/`pm`). Qualifiers after a number (`max`, `plus`, `per`, `each`, `or so`, `give or take`, `at least`) and before one (`a minimum of`, `average of`, `upper bound of`) all read as approximators, as do bare quantity words (`hundreds`, `tens of`, `a single`, and on metric claims `single`, `once`, `null`, `zip`, `nada`). Reason: each shape states a number without stating it.
- **D37, universal words.** `all`, `every`, `each` and `both` fire when the word reaches a label: on a metric claim the label must be a cited one (`both` with `and` coordination is exempt), on a fact-only claim it must be a snapshot label no cited statement holds. Both paths report `L1B_UNVERIFIABLE_QUANTITY`. Reason: "all" claims every member, and the cited evidence never does.
- **D38, time scope, and the time words I took out.** `today`, `yesterday`, weekday names, `this`/`last`/`past`/`next` phrases, `all day`, `in the morning`, `a month`, `per year` and rate words like `daily` fire as quantities, on metric claims only; dates and valid clock times are blanked first, and a clock only counts with an allowed lead-in and no measure word after it. My rulings on existing texts: "this week" came out of G12's first sentence, and "today" came out of three gate tests, because the words contributed nothing where they stood. Reason: a time word moves the number off the cited window, and a word that moves nothing should not sit in a pinned sentence.
- **D39, the quantity kinds.** The scan returns kind tags and any non-empty set is one `L1B_UNVERIFIABLE_QUANTITY`: always on, `fraction`, `multiplicative`, `vague`, `rate`, `spoken`, `tally`, `approximator`, `symbol`, `clock`, `roman`, `ordinal` and `quantity`; metric-claims only, lowercase `roman`, `universal`, spelled ordinals past tenth, digit fraction forms, `range`, `glued` and `time`. `half` stays free beside a backed 50. Reason: one code for the card, many names inside for the tests.
- **D40, negation phrases and non-zero.** The negator list gains the phrases `rather than`, `instead of`, `anything but`, `far from`, `other than`, `apart from`, `aside from` and `except for`. `no` or `zero` before a cited label is a stated zero only when the cited value is actually 0; before a nonzero label it is a number without backing, anywhere else a negated claim. The `zero` in `non-zero`, `nonzero` and `non zero` is never a stated zero. Reason: the phrases negate exactly like the single words, and a stated zero is only true at zero.
- **D41, every side a fact-only claim states.** Each direction side the claim carries (up, down, same, with hyphen compounds read and phrasal particles hidden first) must be carried by a cited statement too, or the claim fails. Compounds read as their head: `up-tick` is up, while `up-to-date`, `up-front` forms and `follow-up`, `write-up`, `set-up`, `sign-up`, `top-down` read as nothing. Reason: a fact-only claim borrows every side it states from its facts.
- **D42, compounds that name a period, which reverses part of D9.** `second to last`, `next to last`, `before last`, `last but one` and `penultimate`, spaced or hyphenated, read as `prior`; `third to last` reads as `earlier`; their own words never count as period words. This reverses the D9 position that a hyphen compound stays one free token: where the compound names a period, the period rules read it. Word senses that are not periods are stripped first: `at last`, `last year`, `last week`, `last minute`, `last place`, `earlier today`, `earlier than` and their kin name no period. Reason: the compound either points at a period I price or it points at nothing.
- **D43, private terms.** A hyphen- or dot-joined name is one name and fires only whole, never on its parts; a spaced term can fire on one long word alone; a one-word term keeps its word. The leet, one-edit and reversal arms run on those single words. Reason: a joined name read in parts would fail ordinary prose, and a spaced term hiding one word is still the term.
- **D44, raw literals.** The sequence rule stays everywhere: the literal's tokens as a consecutive run, punctuation ignored. On claims the bag rule joins it: with two or more content words, every one matched anywhere inside a small window — exact, one-edit for long words, prefix for the rest — fires `L1_RAW_VALUE`. Dropped small words and reorders are closed there; the outbound path keeps sequence only, deliberately. Reason: a claim that carries every word of the literal carries the literal.
- **D45, instructions, questions and phrases.** Strong verbs (`ship`, `take`, `start`, `focus` and the rest) fire bare at a clause start, with guards for `of`, direction words, a copula or auxiliary in second or third seat, and noun-use words; ambiguous verbs (`walk`, `rest`, `read`, `plan`, `push` and the rest) need a determiner, a number, `commit to`, or nothing after them. Joined (`and`/`but`/`or` plus verb plus object), resumed (`so`/`then` plus verb) and bracketed forms count. Any question mark fires, as do question openers and the listed suggestion phrases (`ought to`, `please`, `let's`, `you could`, `why not`, `recommend`, `suggest` and the rest), and `time to` at a clause start. Reason: a claim states, and each of these asks, tells or nudges instead.
- **D46, a commitment's title in a claim.** The whole title of two or more tokens, or its object (the words after the first, for titles of three or more), occurring as consecutive tokens fires `L1_ADVICE`, unless a cited fact's statement carries the same run; a determiner- and number-dropped match of three or more tokens fires the same way. Reason: quoting the title back as a finding is an instruction wearing a statement's clothes.
- **D47, language lists, and entries that close an attack, not a class.** Dutch joins the five pinned languages (direction `stijgt`, `stegen`, `daalt`, `daalden`, `groeit`, `krimpt`; numbers `twee`, `drie`, `vijf`, `zes`, `zeven`, `negen`, `tien`; advice `verzend`, `stuur`, `moet`, `probeer`), and the foreign token sets are the union of all six. Each entry closes the attack in front of me, not the language: no entry claims to cover its class, and the ASCII arm stays the only arm that does not depend on enumerating words. Reason: honest lists name what they caught.
- **D48, `verify_claims` as a public subset.** The public checker keeps the shared core: evidence present and known, exact value match, number-without-ref, label-missing, series direction, named-metric checks with time scope, the `text_check_codes` verbatims except advice, and its own advice word list. It adds what a bare checker needs: only labelled metrics back numbers on a labelled claim, whole-word sibling and naming checks, label caps, and the time-word-outside-the-list check. It leaves to the gate what only the gate reads: negation, quantity words and forms, imperatives, time-order versus named-period comparisons, period compounds, value-period binding, language, look-alike private terms, and the raw bag rule. Reason: the public subset must stay small enough to run anywhere, and each exclusion is pinned with its reason in the parity tests.
- **D49, empty text and links.** A claim with no letter or digit in it is unsafe, as is any claim holding a link (`http://`, `https://` or `www.`). Unsafe characters reject on claims and are stripped silently everywhere else. Reason: a claim that says nothing, or points elsewhere, is not checkable.

## Risks

- **Over-blocking ordinary model prose.** Negation anywhere (D9), imperative detection, the ASCII-letters language arm, vague-quantity words (`several`, `many`), Roman-numeral detection and the comparison vocabulary can all reject true sentences a model would naturally write. Mitigated by the stated-zero exception, the noun-use, `of`, direction-word and copula guards, the backed-50 exception for `half`, the fact-only exemptions for ordinals and clock times, the verbatim-cited-statement language exemption, the three-stopword language floor, the narrowed Roman grammar, and the D18 two-way measurement with `newly_blocked` reported by code; the session note must report the blind over-blocking count by code and O1 separately, so a rule that bites is visible, not anecdotal. One true sentence is blocked on purpose (O1); that is a cost of D9, stated, not a surprise. Roman numerals of up to three letters that use `L, C, D` or `M` stay free because they collide with abbreviations such as `ML` and `CI`. The foreign words `vier` and `cinque` stay on the pinned lists as rare dictionary words and can block a claim that uses them in English.
- **An English sentence quoting a foreign word fails.** D12 arm (c) rejects any non-ASCII letter in a claim outside cited labels and tokens quoted verbatim from a cited fact's statement, so "café" or a foreign place name in an English claim is blocked unless the cited fact carries it. That is a named, accepted risk; it is claim-only, so titles and quoted fact statements on the outbound path are not hit.
- **The fact-only label arm cannot be measured by the blind files.** That arm is gated on a direction word (D11, D14), real snapshots hold ordinary words as labels (`Chat, Video, Programming, busy, deep, family, feed` in Ticket 9's seeded run; `code, comms, feed, browse, media, other` from the real collector), and the runner's fixed context has too few labels for the blind files to show it. The reviewer checks it separately on a Ticket 9 snapshot, and the session note says so.
- **Shared labels stay shared.** Two metrics that share a label can still swap (A20); a claim naming the right metric, period and direction can still be false in its other words outside an eligible comparison (Limits). D11 narrows the label hole to genuinely uncited labels; it does not close the swap. These are disclosed, not fixed, and the README must not imply otherwise.
- **Very long decimal tokens are slow, and that is a named non-issue.** Measured on the unfixed gate: a 20,000-place token takes 0.19 s and a 2,000,000-place token ran over three minutes, because the scan is superlinear. A model's output is capped well short of that, so this is named here as a non-issue, not a fix. The D15 guard stops the raise; it does not change the scan's cost.
- **Closed lists invite round 2.** Every pinned list in D8, D9, D12 and D13 is a target for the fresh attack session. That is the design: round 2 measures list coverage honestly, and list-entry additions and closable new rules are ordinary Step 11 fixes.
- **Confusable coverage is partial.** The pinned Cyrillic and Greek lookalikes close the A29 mechanism, not the Unicode confusable space; unlisted scripts are caught on claims only by D12 arm (c) (any non-ASCII letter), and ASCII phonetic respellings of private terms are a named limit. Widening the map later belongs in `normalize.py` with new pins, not in gate code.
- **`normalize_text` consumers beyond this ticket.** Ticket 17a will import it and Ticket 9's fact checks call `extract_number_tokens`; both are protected by idempotence, by case preservation (D4), by the unchanged token contract (D8, D22), and by strict pyright on `framework/`. A change either ticket needs to `normalize_text` is a plan amendment, because red-team pins depend on its exact steps.
- **The frozen stamp and the one-commit rule.** Stage 1 stamps the base commit because no implementation commit exists yet; after the single Step 12 commit, `gate_commit` in the frozen file names the unfixed gate, which is the point. `gate_files_sha256` and `gate_dirty` (D3) are what make the round-2 stamp honest despite the dirty tree, and no patch reproduces it: the attacked draft was discarded (D3). A reader reproducing round 1 from its commit (D3) must use a separate worktree so the branch is undisturbed.
- **Inspect counts drift if cases are added carelessly.** The briefing Inspect tasks derive from `evals/briefing_cases.py`, so every added case changes task sizes; AT7's log, not memory, is the record.
- **Re-gated product drafts narrow seven rules.** Ticket 16b's stored product-prompt drafts, re-run on this gate with no model calls, carry true sentences the main gate passed and this gate rejects, each narrowed in place: in `since_last` `last card` counts as `last` (the delta is the change since the last card) and stays a non-period sense elsewhere; the title rule skips the pick after `this hour goes to/toward/towards` in its clause while advice phrases and imperatives still read it; `ahead` after day(s), week(s), month(s), hour(s) or time no longer ranks while `ahead of` still does; `steady`/`stable` count as same-direction only after a cited label or the listed copulas, never as adjectives; on fact-only claims `a single` fires only before a snapshot label, unchanged on metric claims; `tied` directly before `to` reads as connected, not equal, so it states no direction, while bare `tied` and `tied with` still state sameness; and the words after `this hour goes` to its clause end name the pick even with no `to`, so neither the title rule nor the other-metric label check reads them there while every other rule still does.

## Limits (stated in `docs/redteam/README.md` and the session note; kept out of scope)

Two limits are allowed and stated plainly, with the [numbers.py](../../framework/briefing/numbers.py) header rewritten to match what is true after this ticket (the implementer may adjust wording, not substance; the fact-only sentence at [numbers.py:12](../../framework/briefing/numbers.py:12) comes out, because D14 closes it, and the `twenty-one` and absolute-backing sentences are updated for D8):

1. A sentence naming the right metric, period and direction that is false in its other words — including direction words outside the pinned lists in single-ref and fact-only claims (the comparison vocabulary closes this class only for eligible 2–3 ref comparisons), evaluative prose like A25's, and claims whose only fault is word choice no list covers.
2. In a multi-ref claim, values are not bound to their order in the sentence. The gate binds a value to a period only where the sentence writes them side by side (D21); a value placed any other way, as in "Pushes in prior and last were 0 and 1", is not bound.

Further named limits from the decisions: direction words outside the pinned lists and outside the pinned foreign lists, in single-ref and fact-only claims; unlisted-language ASCII claims whose words are in no pinned list (non-ASCII letters are closed by D12 arm (c)); Roman numerals of up to three letters that use `L, C, D` or `M`, which stay free because they collide with abbreviations (D8); a name holding a number word that no cited fact evidences, such as "Pushes to seven-tower were 0 in last." citing only the metric, and `3D` in a category or tag name (D22); quantity spellings outside the closed lists, including single tally strokes, novel fraction spellings, and a percent sign on `calendar.busy_hours` — the one metric where a percent token is accepted — and signed or absolute-value backing inside `since_last`, which stays as pinned (G20); valid clock times used as ratios when they follow an allowed preposition; private-term obfuscations by phonetic spelling, translation, description or initials (digit forms, masks, one-edit misspellings of terms of 6+ chars and reversals are closed on claims); the raw literal with a content word dropped (reorders and dropped small words are closed on claims; sequence-only on the outbound path, deliberately); implicit advice with no marker (D13); negated true statements, which fail closed by design (O1 is the pinned instance, counted in Docs); rounding to a token's stated places for tokens with decimals (the A18 zero-places case is fixed, D8). And the standing caution, printed in `docs/redteam/README.md` without softening: a list of attacks that fails is evidence about those attacks, not proof the gate is complete.
