## Goal

Ticket 1 — toolchain. After this ticket, `make check` runs green locally and in CI on an almost empty project: a `uv` project on Python 3.12 with one trivial package, one trivial test, one offline hello Inspect task, and no app code.

Grounding: [AGENTS.md](../../AGENTS.md) (Commands are still marked planned (ticket 1)), [docs/WORKFLOW.md](../WORKFLOW.md) §2 steps 3–4 and §5–§6, [docs/SPEC.md](../SPEC.md) §5.2 ("verify current API on day 1; pin the version").

## Success Criteria

- `make check`, `make test`, `make eval`, and `make demo` all exist and pass locally with no API keys set.
- The same `make check` passes in GitHub Actions on pull requests and on pushes to `main`.
- Every acceptance test below fails on `main` today (no `Makefile`, no package) and passes on the ticket branch.
- No app code, no gate layers (L0–L4), no mutants, and no hidden-criteria handling beyond noting it as a follow-up.

## Approach

Use `uv` as the only environment and dependency tool. Commit `pyproject.toml` and the generated `uv.lock`; do not hand-edit the lockfile. Keep all tool configuration in `pyproject.toml` where the tool supports it (ruff, pyright, pytest), so `make check` and CI run identical commands. `make eval` runs a single hello Inspect task with Inspect's built-in mock model (`mockllm/model`), so it needs no network and no API key. `gitleaks` is a standalone binary, not a Python dependency: `make check` fails with a clear error message if `gitleaks` is not on `PATH` (it never skips), and runs `gitleaks git --redact`. CI installs `gitleaks` with checksum verification.

Key decisions:

- Python pinned to 3.12 via `pyproject.toml` (`requires-python`) and `.python-version`; local system Python (currently 3.15) is not used directly.
- Pyright runs in standard mode for the whole repo, with strict for `framework/` (`typeCheckingMode = "standard"`, `strict = ["framework"]`).
- The hello eval's pass condition is: exit 0, log written, and the log's status read back as `"success"` (AT4) — not exit code alone, and not a model score. First verify how the pinned Inspect version's mock model produces output, then set the scorer/target so the run is deterministic. Pin `inspect-ai` in `uv.lock` after that check, per SPEC §5.2.
- No versions are invented in this plan. Dependency versions resolve at implementation time and are pinned by `uv.lock`; the `gitleaks` version and its checksum in CI are pinned to whatever is current and verified working on the implementation day.
- Branch first: before implementing, `git switch -c t1-toolchain`. This plan is committed on that branch, never on `main`.

## Risks

- **Inspect API drift.** The mock model's output behaviour differs across Inspect versions. Mitigated by step 5: verify against the pinned version on day 1 and pin in `uv.lock` (SPEC §5.2). This is the highest-risk validation step.
- **Pyright modes.** Standard mode repo-wide with `strict = ["framework"]` must not flag the skeleton's test/eval files under standard, nor the empty `framework/` package under strict. If strict flags the trivial `__init__.py`, fix the code, not the mode.
- **`gitleaks` availability.** It is not a `uv` dependency. `make check` never skips it: missing binary means a clear failure, locally and in CI. CI therefore installs a pinned `gitleaks` binary and verifies its checksum before `make check`; `gitleaks git --redact` needs full history, hence `fetch-depth: 0`. A checksum mismatch fails CI rather than running an unverified binary.
- **Pre-commit first run needs network** to fetch hook environments (the `gitleaks` hook; the ruff hooks are `repo: local` and use the `uv.lock` environment). Local and CI runs after the first are cached; tests themselves stay offline (AGENTS.md hard rule).
- **Hidden-criteria CI guard is deferred (decided).** AGENTS.md's last line promises a CI check that fails PRs committing or copying hidden criteria into the repo. This ticket's CI only runs `make check`, which does not implement that guard. Deferred to a follow-up ticket, together with defining the hidden-criteria format first (the format does not exist yet; building the guard now would mean inventing a format to detect). AGENTS.md's line becomes "Planned (follow-up ticket)".
- **Branch protection** (WORKFLOW §2 step 4) is a GitHub setting Carlos applies by hand; it is not created by this ticket. CI can be green without it.
