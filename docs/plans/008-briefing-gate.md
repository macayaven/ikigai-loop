### Key decisions (binding on the implementer)

- **Package layout.** New package `framework/briefing/` with exactly: `schemas.py` (briefing data models), `context.py` (`GateContext`, `MetricSnapshot`, `ProfileLimits`, `TimeInterval`, `PrivateTerms`, `load_private_terms`), `numbers.py` (number-token extraction), `gate.py` (`Violation`, `GateResult`, `evaluate_briefing` and the per-layer helpers), `__init__.py` (re-exports + `__all__`). No CLI, no renderer, no sender: generation (Wonder/Glimmer) and delivery (ntfy etc.) are out of scope; the gate is the deliverable. Stdlib only beyond pydantic (`decimal`, `re`, `zoneinfo`, `datetime`, `pathlib`); `pyproject.toml`/`uv.lock` untouched; a perceived need for a new dependency stops the ticket for amendment.
- **Schema shape (`framework/briefing/schemas.py`).** All on `SchemaModel`; reuse `NonEmptyStr` from `framework/schemas/events.py`, `Dimension` from `framework/schemas/base.py`, `AwareDatetime` from pydantic. Field-for-field:
  - `SectionType = Literal["overall_state", "since_last", "working", "not_working", "actions"]`
  - `MetricRef`: `metric_id: NonEmptyStr`, `value: float` with a finite check (`math.isfinite`, so `nan`/`inf` fail validation and become `L0_SCHEMA_INVALID` on the raw path).
  - `Claim`: `id: NonEmptyStr`, `text: NonEmptyStr`, `fact_ids: list[NonEmptyStr] = []`, `metric_refs: list[MetricRef] = []`. (`id` is added to the brief's field list; see Disagreements D6.)
  - `ActionKind = Literal["build", "write", "read", "apply", "outreach", "walk", "exercise", "rest", "music", "social", "plan", "checkin"]` — the proposed fixed enum. It is deliberately orthogonal to `dimension`: `kind` says what the learner will weight (a later learner keeps one weight per kind per profile), `dimension: Dimension` says which ikigai axis it serves. The 12 kinds cover both profiles' draft criteria (build/write/read/apply for Builder; walk/exercise/rest/music/social for Recovery; plan/checkin shared) and nothing profile-specific is banned at L0/L1 — "Recovery never gets programming" is a later L2 criterion, not a kind exclusion.
  - `Action`: `id: NonEmptyStr`, `kind: ActionKind`, `text: NonEmptyStr`, `dimension: Dimension`, `proposed_start: AwareDatetime`, `proposed_end: AwareDatetime`, with a model validator `proposed_end > proposed_start` (on the raw path this surfaces as `L0_SCHEMA_INVALID` at the action's location).
  - `Section`: `type: SectionType`, `claims: list[Claim] = []`, `actions: list[Action] = []`. No per-type claim/action shape is enforced by the schema itself; shape counts are L0 gate checks so the 4-actions mutant gets `L0_ACTION_COUNT`, not a generic validation error. Actions are only meaningful in the `actions` section: a non-`actions` section carrying actions is `L0_ACTION_COUNT` at that section.
  - `Briefing`: `id: NonEmptyStr`, `profile_id: NonEmptyStr`, `subject_id: NonEmptyStr`, `slot: AwareDatetime`, `parent_briefing_id: NonEmptyStr | None = None`, `sections: list[Section]`. Section has no `id` field; the section `type` is its identity (see L0 duplicate rule).
- **JSON Schema export.** `Briefing`, `Section`, `Claim`, `Action`, `MetricRef`, `MetricSnapshot`, `TimeInterval`, `ProfileLimits`, `GateContext` are appended to `EXPORTED_MODELS` in `framework/schemas/export_schemas.py` (imports from `framework.briefing.*`), the export command is run, and the nine new `schemas/*.json` files plus the `find_drift` test cover them. `Violation`/`GateResult`/`PrivateTerms` are frozen dataclasses in `gate.py`/`context.py`, not `SchemaModel`s, and are not exported (gate output is an internal result, not a wire contract).
- **GateContext (`framework/briefing/context.py`).** All models on `SchemaModel`:
  - `TimeInterval`: `start: AwareDatetime`, `end: AwareDatetime`, validator `end > start`.
  - `MetricSnapshot`: `values: dict[NonEmptyStr, float]`, every value finite (validator). An empty snapshot is valid (a claims-free briefing needs no metrics).
  - `ProfileLimits`: `timezone: NonEmptyStr` (an IANA name, resolved with `ZoneInfo`; an unknown name raises at context construction, never inside the gate), `allowed_start: time`, `allowed_end: time` with `allowed_start < allowed_end` (same-day, non-wrapping window; both profiles are daytime), `max_actions: int = 3` constrained `1 <= max_actions <= 3`. There is deliberately no restricted/evening-window field: the 20:00–22:30 window governs notification priority, the briefing has no priority field, and inventing a gate failure for it would exceed the brief (see C6 and Disagreements D5).
  - `GateContext`: `facts: dict[NonEmptyStr, Fact]` (validator: every key equals its `Fact.id`), `metrics: MetricSnapshot`, `parent_briefing: Briefing | None = None`, `parent_metrics: MetricSnapshot | None = None` (validator: both present or both absent, and when present `parent_briefing.id` is the value briefings must name), `free_intervals: tuple[TimeInterval, ...] = ()`, `busy_intervals: tuple[TimeInterval, ...] = ()`, `limits: ProfileLimits`, `check_slot: bool = True`, `private_terms: tuple[str, ...] = ()`, `private_terms_available: bool = False` (fail closed by default; every fixture sets it explicitly), `raw_metric_ids: frozenset[NonEmptyStr] = frozenset()`, `forbidden_raw_literals: tuple[NonEmptyStr, ...] = ()`. Interval lists may be unsorted and overlapping; the gate normalises (sort + merge) before checking, so context construction order never changes the result. `check_slot` is caller-owned mode, not briefing data: delivered briefings pass `check_slot=True` (the default); undelivered scored cycles and replay pass `check_slot=False`, so a briefing scored for a slot other than its intended delivery slot is not failed on allowed hours. Only `L1_SLOT_OUTSIDE_ALLOWED_HOURS` is gated by it — every other check, including `L1_ACTION_BEFORE_SLOT`, still runs when it is false.
- **Private terms loading (fail closed, review-hardened).** `load_private_terms(environ: Mapping[str, str] | None = None, *, allow_missing_for_tests: bool = False) -> PrivateTerms` in `context.py`, where `PrivateTerms` is a frozen dataclass `(terms: tuple[str, ...], available: bool)`. It reads `HIDDEN_CRITERIA_DIR` from `environ` (default `os.environ`) at call time only. If the variable is unset/empty: return `PrivateTerms((), available=allow_missing_for_tests)` — passing with no terms loaded is possible **only** when the caller passes the explicit test flag `allow_missing_for_tests=True`; every production caller uses the default. If the variable is set: read **only** the file `deny-terms.txt` directly inside it, because the directory may hold other criteria files. Return `PrivateTerms((), available=False)` (fail closed, no exception, no path in any message) when the file is missing, holds no terms, is not UTF-8, or any term line starts with `- ` or `* `. Otherwise parse one term per line, stripped, blank lines and lines starting with `#` ignored, duplicates removed keeping first order, and return `available=True`. Matching is case-insensitive; terms of 3 characters or fewer match whole words only (token boundaries), longer terms keep substring matching. Terms are never logged, never put in a `Violation.message`, and never read by any test from the real directory — tests use `tmp_path` synthetic term files or inject `GateContext.private_terms` directly. The gate emits `L1_PRIVATE_TERMS_UNAVAILABLE` when `context.private_terms_available` is false, so an unavailable list can never silently pass. The `deny-terms.txt` one-term-per-line format is an assumption (the repo nowhere specifies the private list's format; documented in `.env.example` without any real term); see Disagreements D4.
- **Gate entry point and result (`framework/briefing/gate.py`).** Exact signatures:

```python
@dataclass(frozen=True)
class Violation:
    code: str  # one of the stable codes in the table below
    layer: Literal["L0", "L1", "L1b"]
    location: str  # e.g. "sections[actions].claims[claim-1]" or "slot"
    message: str  # generic text; never contains a matched secret/term/value


@dataclass(frozen=True)
class GateResult:
    violations: tuple[Violation, ...]  # sorted by (layer, code, location)

    @property
    def passed(self) -> bool: ...


def evaluate_briefing(
    raw: Briefing | Mapping[str, Any], context: GateContext
) -> GateResult: ...
```

  `raw` is the unvalidated briefing as a mapping (the normal path: Inspect samples and callers hand over JSON-shaped data) or an already-validated `Briefing` (accepted for convenience; L0 then re-checks counts/IDs on the object). A top-level value that is not a mapping is not validatable at all and returns one `L0_SCHEMA_INVALID` at `briefing` — malformed input never raises. Pipeline: (1) pre-scan the raw sections for unknown `type` values — any type that is not a string, is unhashable, or is not one of the five `SectionType` values is `L0_UNKNOWN_SECTION`, one per offending section, located by index; (2) `Briefing.model_validate` — a `ValidationError` becomes one `L0_SCHEMA_INVALID` per error location (`".".join(loc)`), and if validation fails the gate returns the L0 violations only (L1/L1b never run on a shape they cannot trust); (3) L0 counts/required/unique checks on the validated object; (4) L1 text, slot, and interval checks; (5) L1b reconciliation. Layers 4–5 always both run (a briefing collects every violation, not the first), and within a layer every check runs even if a sibling already failed. Identical `(code, location)` pairs are de-duplicated once at the end. Determinism: no `datetime.now`, no randomness, no dict-order dependence — facts/metrics/intervals are looked up by key or sorted before arithmetic, and locations name section types (not input indexes) after validation, so reordering sections cannot change the sorted result.

- **L0 checks, in order.** Required sections are `overall_state`, `working`, `not_working`, `actions` (always) — `since_last` is **not** an unconditional L0 requirement because a first briefing has no parent; its conditional requirement is L1b (`L1B_MISSING_SINCE_LAST`, brief item 5). Checks: `L0_UNKNOWN_SECTION` (pre-scan, above); `L0_SCHEMA_INVALID`; `L0_DUPLICATE_SECTION` (same `type` twice; location = the type); `L0_MISSING_SECTION` (a required type absent, one per missing type); `L0_SECTION_COUNT` (more than 5 sections after duplicates — reachable only via duplicates, kept as a guard so the code exists independently); `L0_EMPTY_SECTION` (the `overall_state` section carries 0 claims, or a present `since_last` section carries 0 claims; one violation at the offending section. `working` and `not_working` may carry 0 claims, and a missing `since_last` is never `L0_EMPTY_SECTION` — it is `L1B_MISSING_SINCE_LAST` when a parent exists and no violation for a first briefing); `L0_ACTION_COUNT` (the `actions` section carries fewer than 1 or more than `min(3, limits.max_actions)` actions, or any other section carries any actions; one violation per offending section); `L0_DUPLICATE_ID` (any `id` repeated across the briefing's claims and actions — facts referenced by `fact_ids` are references, not owned IDs, and the briefing's own `id` is not part of the pool; one violation per repeated ID, location = second occurrence). Empty `sections`, a `slot` without timezone, or `proposed_end <= proposed_start` are `L0_SCHEMA_INVALID` via pydantic.
- **L1 checks.** Text scanned is exactly `Claim.text` and `Action.text` of every section (IDs, `metric_id`s, and fact statements are not user-visible prose). Locations name the owning claim/action ID.
  - Secrets (`L1_SECRET`): case-insensitive regex set in `gate.py` that must not match ordinary English. Every token-prefix pattern starts with a word boundary (`\b`, so the prefix is not preceded by a letter, digit, or `_`) and requires at least 16 token characters (`[A-Za-z0-9_-]`) after the prefix: `\bghp_[A-Za-z0-9_-]{16,}`, `\bgho_[A-Za-z0-9_-]{16,}`, `\bgithub_pat_[A-Za-z0-9_-]{16,}`, `\bglpat-[A-Za-z0-9_-]{16,}`, `\bsk-[A-Za-z0-9_-]{16,}`, `\bAKIA[A-Za-z0-9_-]{16,}`, `\bxox[baprs]-[A-Za-z0-9_-]{16,}` (the 16-character minimum applies after the whole prefix, including after `sk-` and after the `xox[baprs]-` letter). The credential pattern is `\bBearer\s+\S{16,}` — the word `Bearer` (case-insensitive) plus a following token of at least 16 non-space characters. A PEM header (`-----BEGIN … PRIVATE KEY-----`) and a labelled assignment `(api[_-]?key|secret|token|password)\s*[:=]\s*\S+` are unchanged (the assignment requires an explicit `key:`/`key=` label, not ordinary prose). A generic hostname arm `\b[A-Za-z0-9-]+(\.[A-Za-z0-9-]+)*\.ts\.net\b` matches any hostname ending in `.ts.net` and contains no real hostname. By construction `task-based`, `risk-free`, and `desk-side` cannot match (`sk-` is mid-word, so there is no word boundary before it, and each has fewer than 16 token characters after it anyway) and the news-carrier phrase in G11 cannot match (its following word is 2 characters); G11 pins all four phrases as passing. A short string after a real prefix (e.g. `sk-short`) is likewise not a secret under this rule — the length floor is the accepted cost of not matching English. One violation per match location, message `secret-like token`.
  - PII (`L1_PII`): email regex `[A-Za-z0-9._%+-]+@[A-Za-z0-9.-]+\.[A-Za-z]{2,}` and a strict international phone regex `\+\d[\d ()-]{7,}\d`. Email is the brief's named mutant; the phone pattern is deliberately narrow (leading `+`, digit-ending) so dates/times/metrics in known-good text cannot trip it. No other PII class is claimed — a deterministic regex gate cannot recognise names/addresses, and the plan does not pretend otherwise (Disagreements D7).
  - Private terms (`L1_PRIVATE_TERM` / `L1_PRIVATE_TERMS_UNAVAILABLE`): if `not context.private_terms_available`, one `L1_PRIVATE_TERMS_UNAVAILABLE` at `briefing` and the term scan is skipped (fail closed, not fail open). Otherwise each term is matched case-insensitively (`str.casefold`, whitespace-collapsed) as a substring of each scanned text; one violation per (term-location) without naming the term (`private term`).
  - Raw Calendar/Health values (`L1_RAW_VALUE`): two deterministic arms, because free text alone cannot carry the meaning "raw" (Disagreements D3). (a) A `metric_ref` whose `metric_id` is in `context.raw_metric_ids` or starts with `raw.` — the value is a raw source value being republished. (b) A scanned text containing any `context.forbidden_raw_literals` entry matched with the same casefold and whitespace collapse as private terms, keeping the token-boundary check — lowercase, uppercase, and double-spaced variants of a literal are all rejected. One violation per location; the literal is never echoed.
  - Slot (`L1_SLOT_OUTSIDE_ALLOWED_HOURS`): checked only when `context.check_slot` is true; when it is false the check is skipped entirely and no other check changes. `briefing.slot.astimezone(ZoneInfo(limits.timezone)).time()` must satisfy `allowed_start <= t < allowed_end` (start inclusive, end exclusive, so 13:00 passes and 23:30 fails for Builder). One violation at `slot`.
  - Action start (`L1_ACTION_BEFORE_SLOT`): every action's `proposed_start` must satisfy `proposed_start >= briefing.slot` (an action starting exactly at the slot passes). One violation per offending action, at that action. This check applies even when `context.check_slot` is false — skipping allowed-hours for undelivered/replay scoring must not let a briefing propose work in its own past.
  - Action intervals (`L1_ACTION_IN_BUSY_INTERVAL` / `L1_ACTION_NOT_FREE`): intervals are half-open `[start, end)`. An action overlapping any busy interval (`start < busy.end and busy.start < end`) gets `L1_ACTION_IN_BUSY_INTERVAL` and the not-free check is suppressed for that action (busy is the more specific diagnosis; this keeps the busy mutant single-code). Otherwise the action must be fully covered by the merged union of `free_intervals`; any uncovered part gets `L1_ACTION_NOT_FREE`. Touching boundaries (action ends exactly when busy starts) is not an overlap.
  - Repo target (`L1_ACTION_TARGETS_REPO`): case-insensitive substring scan of `Action.text` for `ikigai-loop`, `ikigai_loop`, and `ikigai loop` (the repo's name forms; `Dimension`-style prose about "this repo" without the name is not detectable deterministically and is not claimed). Claims are not scanned for this rule — the brief scopes it to actions ("no action targeting this repo"). This rule has a unit test but is not one of the 20 mutants (the brief's mutant list does not name it).
- **L1b checks.** Evidence presence: every `Claim` in every section (including `actions`-section claims) must carry at least one entry in `fact_ids` or at least one entry in `metric_refs`, else `L1B_CLAIM_WITHOUT_EVIDENCE` at that claim (one per evidenceless claim). Facts: every entry of every `Claim.fact_ids` must be a key of `context.facts`, else `L1B_UNKNOWN_FACT` at that claim (one per missing ID). A fact whose `subject_id != briefing.subject_id` is also `L1B_UNKNOWN_FACT` (a fact from another subject is not evidence for this briefing; same code, message says so). Numbers: number backing compares claim text to `metric_ref` only, with tokens extracted per claim using that claim's cited fact/metric IDs as `known_ids`. A number token extracted from `Claim.text` (spec below) is backed iff at least one `metric_ref` on that same claim, rounded half-up (`ROUND_HALF_UP`) to the token's decimal places (digits after the token's decimal point; 0 for an integer or spelled-out token) and taken by absolute value, equals the token's absolute value, else `L1B_NUMBER_WITHOUT_METRIC_REF` (one per unbacked token, located at the claim). So text `21.2` is backed by a ref of `21.1544` (rounds to `21.2` at 1 place) and text `down 5` is backed by a ref of `-5` (absolute values `5 == 5`); G12 pins both. This rounding/absolute comparison applies **only** to the text-to-ref backing check: a `metric_ref` against the current snapshot, or against the `since_last` delta, still compares exactly (below), so a ref that rounds to the text but differs from the snapshot still fails `L1B_METRIC_VALUE_MISMATCH`/`L1B_DELTA_MISMATCH`. Metric equality: for claims outside `since_last`, every `metric_ref` must exist in `context.metrics.values` (`L1B_UNKNOWN_METRIC` if absent) and equal it exactly (`L1B_METRIC_VALUE_MISMATCH`). Inside `since_last`, every `metric_ref` must satisfy the delta rule instead (below); the snapshot-equality rule does not apply there (the brief's two clauses conflict if both are applied; Disagreements D1). Parent/delta: if `briefing.parent_briefing_id is not None` — it must equal `context.parent_briefing.id` with `parent_metrics` present, the parent must carry the same `profile_id` and `subject_id` as the briefing, and the parent `slot` must be strictly before the child `slot`, else `L1B_PARENT_MISMATCH` at `parent_briefing_id`; the `since_last` section must exist, else `L1B_MISSING_SINCE_LAST` at `sections`; and each `since_last` `metric_ref.value` must equal `Decimal(str(current)) - Decimal(str(parent))` for its `metric_id` (metric missing from either snapshot → `L1B_DELTA_MISMATCH`). If `parent_briefing_id is None` while the context holds a parent briefing/snapshot pair, that is also `L1B_PARENT_MISMATCH` at `parent_briefing_id` (a parented context the briefing does not name). If `parent_briefing_id is None` but a `since_last` section is present, `L1B_SINCE_LAST_WITHOUT_PARENT` at that section (no baseline exists to reconcile against). Snapshot/delta comparisons use `Decimal(str(value))` with no rounding and no float tolerance, so a wrong-value mutant off by any representable amount fails; text tokens are the only values that pass through the half-up/absolute backing comparison.
- **Number-token extraction (`framework/briefing/numbers.py`, review-hardened).** Signature: `extract_number_tokens(text: str, known_ids: Collection[str] = ()) -> tuple[NumberToken, ...]`, `NumberToken` a frozen dataclass `(raw: str, value: Decimal, start: int, places: int)` in left-to-right order (`places` = the token's decimal places, for the half-up backing comparison; `0` for spelled-out tokens). `known_ids` holds the fact/metric IDs cited on the claim being scanned. The function is pure text work, used only for the L1b backing check (L1 safety scans always see the unmasked text). Principle: when in doubt the gate rejects — a bare year, an uncited identifier, a dotted version, a colon time before a duration word, and a spelled-out quantity are all tokens. Algorithm, in order:
  1. **Mask full dates only.** Replace each match with spaces (same length, offsets preserved): ISO dates `\d{4}-\d{2}-\d{2}`, day-first dates `\d{1,2}/\d{1,2}/\d{2,4}`, and month-name dates (`31 Oct`, `Oct 31`, optionally with a trailing 4-digit year) with **capitalized** month names only (Jan–Dec full or 3-letter, case-sensitive), so `May 9` is a date while `may 9` is not. A bare year is masked **only inside a full date** — outside one (`In 2026`, `of 2026`, `Seen 2026 units`) it is a number token.
  2. **Mask clock times not followed by a duration word.** `\d{1,2}:\d{2}(:\d{2})?\s*(am|pm)?` with a negative lookahead for a duration word (`hours?`, `hrs?`, `h`, `minutes?`, `mins?`, `min`, case-insensitive), so `13:30` is free but `8:30 hours` yields tokens `8` and `30`. Ranges built from plain times (`13:00–23:30`) mask as two times plus the dash. Durations in words (`25 min`, `7.5 h`) are **not** masked — their digits are quantities and need backing.
  3. **Mask cited identifiers/references only.** An identifier `[A-Za-z][A-Za-z0-9_-]*\d[A-Za-z0-9_-]*` (e.g. `brf_01`, `claim-2`, `v14`, `hrv-99`, `steps9065`) or a colon reference `[A-Za-z][A-Za-z0-9_-]*:[A-Za-z0-9_.-]+` (e.g. `fact:212`, `sleep:9`) is blanked **only when the whole match exactly equals a fact/metric ID cited on that same claim**; otherwise its digits are tokens. Dotted versions (`1.2.3`) are never masked — `1.2.3 hours` yields tokens `1.2` and `3`. Ordinals `\d+(st|nd|rd|th)` are still blanked (enumeration, not measurement).
  4. **Extract digits.** On the masked text, scan left to right for `(?:\d{1,3}(?:,\d{3})+|\d+)(?:\.\d+)?%?`, optionally preceded by a hyphen-minus. A hyphen is taken as a minus sign **only when it is not preceded by a letter or a digit** (start of text, or preceded by whitespace/punctuation) and a digit follows it; in every other position the hyphen is a separator and starts no sign. So `3-5` yields exactly two tokens, `3` and `5` (the hyphen follows the digit `3`), `down -5` yields the signed token `-5`, and `well-known 5` yields `5`. Parse each token with `Decimal` after removing thousands commas. Each `NumberToken` also records its decimal places (digits after the decimal point in the raw token, `0` for integers; a trailing `%` does not count) because the backing check rounds refs to exactly that precision. A trailing `%` is presentational — `50%` has value `Decimal("50")`, so a percentage claim must cite a metric whose value is `50`, not `0.5` (the convention is stated here because the brief does not fix it). Scientific notation is not a token.
  5. **Extract spelled-out quantities.** A number word (`one`–`twenty`, `thirty`–`ninety` by tens, case-insensitive) is a token **only when directly followed by a unit word** (`hours`, `hr`, `minutes`, `min`, `steps`, `days`, `percent`), so `Slept nine hours` yields token `nine` (= 9, places 0) while `one of the days` is free. Digit and word tokens merge by offset, left to right.
  Full dates, plain times, ordinals, cited references, and spelled-out non-quantities are thus allowed in prose without a metric, while every measured quantity — bare years, uncited IDs, dotted versions, colon times before duration words, counts, word durations, spelled-out quantities, percentages, scores — must be backed on its own claim. Tests pin each masking arm, each extraction arm, the hyphen rule (`3-5`, `down -5`), token decimal places, and the eleven review rejection strings separately (`tests/test_briefing_numbers.py`, `tests/test_briefing_gate.py`). Two disclosed gaps, accepted: the gate checks that a value matches a ref, not that the prose attaches it to the right metric; and backing compares absolute values, so direction words (`down`, `up`) are not checked.

### Inspect tasks (`evals/briefing_gate.py`, mirroring `evals/hello.py`)

Unlike the framework gate, the Inspect layer follows `hello.py`'s shape so logs are comparable: `@task` functions `briefing_l0()`, `briefing_l1()`, `briefing_l1b()`, and `briefing_gate()` (all layers), each `Task(dataset=[...], solver=[generate()], scorer=<deterministic scorer>)`, run offline with `--model mockllm/model` and `--log-dir logs`. Each `Sample` is built from one `Case` in `briefing_cases.py`: `id=case.name`, `input` is a fixed instruction string (the mock completion is ignored), `target` is `PASS` for known-good cases and the comma-joined expected codes for mutants, `metadata={"briefing": case.briefing, "context": case.context.model_dump(mode="json"), "layers": [...]}`. The scorer is one `@scorer` factory `gate_scorer(layers)` that reconstructs `GateContext.model_validate(metadata["context"])`, calls `evaluate_briefing`, filters to its layers, and returns `Score(value=CORRECT if the filtered code list equals the target's else INCORRECT, answer=<comma-joined actual codes>, explanation=<every violation as "CODE @ location">)`. The scorer never reads `state.output` content for its decision beyond requiring the run completed; determinism comes from the gate, not the model — this is a meta-eval harness wearing Inspect's log format, and the plan says so rather than calling it an LLM eval (Disagreements D8). Layer tasks include every case; a case whose defect lives in another layer is expected to **pass** that layer's task (target = its codes filtered to the layer, `PASS` when empty), which tests layer isolation as well as detection.

## Risks

- **Number-backing false rejections (the 0-false-rejection target is the hard part).** Any digit a briefing author writes casually ("3 days", "option 1") needs a metric or the gate fails a good briefing. The review hardened the extractor the other way instead: bare years, uncited identifiers, dotted versions, colon times before duration words, and spelled-out quantities are all tokens now, so authors must cite metrics even more often. Mitigated by the masking spec (full dates, plain times, ordinals, cited references, spelled-out non-quantities stay free), by G9 proving date/time-only prose passes, and by pinning every mask arm in `tests/test_briefing_numbers.py` — but the residual risk is real: claim authors must learn to either cite a metric or avoid digits. This is accepted as the price of L1b and is stated in Disagreements D2, not hidden.
- **Two disclosed L1b gaps (accepted, documented).** The gate checks that a value matches a ref, not that the prose attaches it to the right metric (a claim saying "focus is 90" backed by a walk-minutes ref of 90 passes). Backing compares absolute values, so direction words (`down 5` backed by `-5`) are not checked. Closing either gap needs prose understanding beyond a deterministic gate; both are recorded in the session note for a later L2 criterion, not fixed here.
- **Known number-extraction misses, to revisit in T11.** Compound spelled-out numbers (`ten thousand steps`, `eight and a half hours`); a month plus a year-like number (`May 2000 steps`); a date ending in a year-like number (`12/25/2000 steps`); a time before a non-duration unit (`10:30 steps`).
- **Raw-value detection depends on the caller supplying the raw set.** If a future caller builds a `GateContext` with empty `raw_metric_ids`/`forbidden_raw_literals`, raw values pass arm (b) silently. Mitigated by making the sets explicit `GateContext` fields the caller must consciously populate, by M7 pinning arm (a), and by the `raw.` prefix convention failing any `raw.*` metric ref even when the set is empty.
- **Private-terms file format is assumed.** If the real list is not one-term-per-line text, `load_private_terms` loads the wrong terms and L1 silently checks the wrong list. Mitigated by fail-closed availability, by never claiming in evidence that the real list was inspected (the implementer states the format assumption in the session note for Carlos to confirm against the real directory himself), and by the loader being one function to correct.
- **Float snapshots vs Decimal comparisons.** Snapshot values arrive as JSON floats; a value like `0.1` stringifies cleanly via `str()`, but a computed snapshot value (e.g. `0.30000000000000004`) would mismatch its own claim. Mitigated by keeping snapshot/delta comparisons exact in `Decimal(str(...))` (the half-up/absolute rounding applies only to text-to-ref backing, G12) and by G4's decimal/percentage cases; snapshot producers must emit decimal-clean values, which synthetic fixtures do by construction.
- **`since_last` semantics could be read the other way.** If a later generator emits current values (not deltas) inside `since_last`, every such briefing fails `L1B_DELTA_MISMATCH`. The plan pins the delta reading (Disagreements D1) and G2/M13 exercise it; changing the convention later is a code + fixture amendment, not a silent edit.
- **Inspect scorer ignoring the model looks unusual in review.** Mitigated by naming it a meta-eval harness in the module docstring and evidence note, mirroring `hello.py`'s logging exactly, and keeping the pytest meta-eval (AT7) as the CI gate so no claim rests on the mock run alone.
- **Section locations after validation lose input order.** Locations name section types, so a violation in a duplicated section is attributed to the type, not the second copy. Accepted: duplicates already fail L0, and type-named locations keep results reorder-invariant (AT6).

## Disagreements with the brief (for approval)

None of these blocks the plan; each is resolved by the pinned reading stated, and approval of this plan accepts that reading. They are listed because the brief asks for them explicitly.

- **D1 — `since_last` metric refs cannot both "equal the MetricSnapshot" and "equal current minus parent".** Brief item 5 states both. Resolution: refs outside `since_last` equal the current snapshot; refs inside `since_last` are deltas and equal current minus parent. Applying both rules inside `since_last` would make every correct delta briefing fail, so the snapshot clause is read as scoped to non-`since_last` claims.
- **D2 — "Every number token must be backed" over-fires on dates, times, IDs, and enumerations, and under-fires on spelled-out numbers.** A literal reading rejects "on 2026-10-31 at 14:30" (G9 must pass) and misses "seven hours". Resolution: the mask-then-extract spec in Approach (full dates/plain times/ordinals/cited references free; bare years, uncited IDs, dotted versions, colon times before duration words, and digits in words are quantities). Spelled-out numbers are tokens only before unit words (`nine hours` is a quantity, `one of the days` stays free) — the remaining bare-word gap is accepted and documented rather than solved with a full word-number parser that would create its own false positives.
- **D3 — "No raw Calendar or Health values" is not checkable from briefing text alone.** Raw-ness is provenance, not shape: `62` is raw in one briefing and an aggregate in another, and a synonym list would miss the next phrasing. Resolution: the caller supplies `raw_metric_ids`/`forbidden_raw_literals` in `GateContext`, plus the `raw.*` prefix arm that needs no caller help. A pattern-only gate is rejected as a false guarantee.
- **D4 — The private list's format and file layout are nowhere specified in the repo.** Brief item 4 assumes terms can be "loaded from `HIDDEN_CRITERIA_DIR`". Resolution: the pinned `deny-terms.txt`-only loader (one term per line, `#` comments and blanks ignored, `- `/`* ` lines and missing/empty/non-UTF-8 files fail closed) with fail-closed availability and the explicit `allow_missing_for_tests` flag; the implementer never opens the real directory, and the format assumption is flagged in the evidence note for Carlos to verify. If the real format differs, only `load_private_terms` changes.
- **D5 — The 20:00–22:30 window is a notification-priority rule, not a send/no-send rule, so the gate does not enforce it.** Brief item 4 lists L1 checks; the window appears in neither the slot rule (allowed hours) nor the action rule (free intervals), and `Briefing` has no priority field to demote. Resolution: `ProfileLimits` carries allowed hours only, G6 pins a 21:00 briefing passing on 2026-10-31, and the window is handled by the `profiles/builder.md` wording edit. Inventing a gate failure here would reject briefings the brief itself allows until Nov 4.
- **D6 — The brief's `Claim` has no `id`, but L0 requires unique IDs and violations need stable locations.** Resolution: `Claim.id: NonEmptyStr` is added (the smallest schema addition that makes brief items 3 and 6 implementable). `Section` gets no `id`; its `type` is the identity, and duplicate types are the duplicate-ID analogue for sections.
- **D7 — "No secrets; no PII" overpromises what a deterministic gate can prove.** Regexes catch the pinned token/email shapes (and the M4/M5 mutants) and miss novel shapes by construction. Resolution: the gate claims exactly its regex set (pinned in Approach and tests), messages never echo a match, and gitleaks stays the repo-level backstop. The plan does not describe L1 as a proof of absence.
- **D8 — An Inspect scorer that ignores the mock completion is a meta-eval runner, not a model eval.** Brief item 6 asks for it anyway ("deterministic scorers, offline on mockllm, logged like `evals/hello.py`"), and it is the right tool for reproducible gate logs. Resolution: build it exactly that way, name it honestly in the module docstring and evidence note, and keep the binding CI claim on the pytest meta-eval (AT7), not on the Inspect run.
