## Risks

- **First paint waits on an 8 MB load.** On a slow phone the auto-run catch can arrive half a minute after the heading. Mitigation: the steps and the pre-filled form are readable HTML before any script runs, the status names the wait honestly, and the result appears in place without a scroll jump. Residual risk accepted: the ticket forbids new origins and a smaller checker is a different ticket.
- **Re-pinning can hide a verdict change.** Updating pinned wording in two test files is the easiest place to smuggle a behaviour change. Mitigation: D1 and AT3 freeze the code, bundle and examples byte-for-byte, AT10 proves the base verdicts were already pinned, and every re-pinned expectation must be named in the session note first.
- **The sneaky example teaches a rule the form cannot explain.** A negation fails even when its number matches, which can puzzle a first-time reader. Mitigation: its pinned sentence ("The sentence says the opposite of the number.") and the honest list both say negation fails, in plain words.
- **Copy drift between page and helper.** Headlines and sentences live in the helper, labels and steps in the page. Mitigation: each string is pinned here once, helper wording is tested in the plain tests, page wording is tested in the page tests, and the helper stays the only source of per-code wording.
- **Time: what is cut first, in order.** If the session runs long, cut in this order and record each cut in the session note: (1) the entrance motion beyond a plain fade; (2) session-note prose beyond the required evidence lines. Never cut: the auto-run, the pre-filled form, the pinned verdict sentences, the honest list staying visible, the JSON move, or any acceptance test. The restructure is one page and one helper; if even that does not fit, the ticket returns to Carlos before 18:00 rather than landing half a page.

## Assumptions

Nobody could answer questions during this session, so each point below was decided here, with its reason. Approval of this plan accepts these readings.

- **A1, the worked example is the false-number file example, in plain form.** "Deploys reached 12 in November." with "November deploys" = 7 is both the ticket's example and the page's current made-up card, and through the plain pipeline it fails with `L1B_METRIC_VALUE_MISMATCH` only (confirmed in this session). The JSON file `false-number.json` itself is not loaded by the auto-run; the plain form is pre-filled with the same sentence and record, so the demo and the tool are one code path.
- **A2, "the plain form can produce" means through `build_checker_input`.** The pinned sentence set in D3 is the seven codes that pipeline can reach plus the fallback. Codes that need labels, units, periods, order, deny terms, advice words or fact citations are JSON-pane only; their existing sentences stay unchanged rather than gaining new wording nobody can reach from the form.
- **A3, the suggested loading wording is improved, not copied.** The ticket's "about ten seconds" conflicts with the page's measured line (3 seconds fast, 15 to 30 slow) that tests already pin. The pinned loading copy keeps the measured times in shorter form, because a promise a slow phone breaks is worse than a longer sentence.
- **A4, `docs/TRUST.md` is not created by this ticket (ruling R1).** The page links to `https://github.com/macayaven/ikigai-loop/blob/main/docs/TRUST.md`, which the trust-page branch creates and which merges before this ticket. No test requires the file on this branch: tests pin only the link's text and address.
- **A5, disabled means the `disabled` attribute, for every check button.** The ticket names Check; applying the same state to the example and Run buttons keeps one rule a visitor can learn, and it replaces the queue-a-click pending mechanism instead of leaving two behaviours alive.
- **A6, theme handling means the operating system setting, as today.** No manual toggle is added: the page already follows `prefers-color-scheme`, a toggle is new state and new script, and the one-session timebox is better spent on the auto-run and the verdicts.
- **A7, one accent and the current verdict colours are kept.** They already pass WCAG AA in both themes (measured in this session and recorded in Goal), so the beauty work is type, spacing and layout. Changing colours would add risk and prove nothing.
- **A8, the smile comes from the catch, not from decoration.** No images, mascots, sound or extra animation are added: the page may load only what it loads today, and the fun the ticket asks for is a clear catch, a headline and one-tap examples. The gentle entrance in D5 is the whole motion budget.
- **A9, the reader's own sentence is checked through the same plain pipeline.** "Try one sentence of their own" needs no new mode: the pre-filled form is editable, sentences without numbers keep today's "wasn't checked" line, and several sentences keep today's per-sentence cards.
- **A10, branch, worktree and bookkeeping follow the repo's workflow.** Work happens on the existing `t25-checker-page` branch in this worktree, tests come first, and the session export plus `CONTRIBUTIONS.md` entry are part of the ticket per the Definition of Done. This plan session itself makes no commit, and the implementation session commits only when asked.
- **A11, no Inspect eval changes.** The checker logic and the gate do not change, so no eval file changes and the "all mutants caught" line of the Definition of Done is proved by the unchanged suite inside `make check`, not by a new log.
