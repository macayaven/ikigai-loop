## Approach

### Key decisions (binding on the implementer; each with its reason)

- **D1, `Commitment` lives in `framework/briefing/schemas.py`; its loader lives in new `framework/briefing/commitments.py`; public text helpers live in `gate.py`.** Reason: `schemas.py` already holds every briefing wire model on `SchemaModel`, so `Commitment` joins the exported set with no new schema home, and the loader stays out of `context.py` to avoid an import cycle. Detail: `context.py` (which defines `GateContext`) imports `Commitment` from `schemas.py` for the new field. The loader needs the gate text verdicts for title validation. Putting the loader in `context.py` and importing gate patterns there would cycle, because `gate.py` imports `context.py` at line 23. So `commitments.py` imports `gate.py` and `schemas.py`. Nothing in `gate.py` or `context.py` imports `commitments.py`. `gate.py` gains two public pure helpers, `text_check_codes(text, *, private_terms=(), forbidden_raw_literals=()) -> tuple[str, ...]` and `action_targets_repo(text) -> bool`. `text_check_codes` covers secrets, PII, advice, and private terms and raw literals when passed, and never returns `L1_ACTION_TARGETS_REPO`. `_l1_text_checks` calls `text_check_codes`; the gate calls `action_targets_repo` on action text only. The loader calls both `text_check_codes` and `action_targets_repo` on each title. No underscore name is imported across modules, because pyright strict rejects that (`reportPrivateUsage`). `framework/briefing/__init__.py` re-exports `Commitment`, `LoadedCommitments`, `load_commitments`, the label types and the two helpers. `gate.py` also gains `action_window_codes(start: datetime, end: datetime, *, slot: datetime, busy_intervals: tuple[TimeInterval, ...], free_intervals: tuple[TimeInterval, ...]) -> tuple[str, ...]` for Ticket 11, because Ticket 11 checks a proposed window before it builds a whole briefing.
- **D2, the loader reports availability, like `load_private_terms`.** `load_commitments(environ: Mapping[str, str] | None = None, *, private_terms: tuple[str, ...] = (), forbidden_raw_literals: tuple[str, ...] = ()) -> LoadedCommitments` reads `IKIGAI_COMMITMENTS_FILE` from `environ` (default `os.environ`) at call time only. `LoadedCommitments` is a frozen dataclass `(commitments: tuple[Commitment, ...], available: bool, reason: str | None)`. `reason` is None on success. On failure it is exactly one value from the closed set `unset`, `unreadable`, `not_utf8`, `invalid_json`, `not_a_list`, `empty`, `invalid_item`, `duplicate_id`, `title_failed`. It is never a path and never file content. Any failure returns `commitments` empty and `available` False: variable unset or empty gives `unset`; missing file, directory path or other `OSError` gives `unreadable`; non UTF-8 bytes give `not_utf8`; a JSON parse error gives `invalid_json`; a top level that is not a list gives `not_a_list`; an empty list gives `empty`; any item failing `Commitment` validation gives `invalid_item`; a duplicate `id` gives `duplicate_id`; any title failing the title checks (D3) gives `title_failed`. The loader catches every failure, including `RecursionError` from deeply nested JSON, and no exception propagates. There are no messages, logs or prints, so no path or content can leak. Reason: a bare empty tuple would make a broken real file look exactly like a model inventing actions, which is the silent block at every card this ticket has to prevent, so T11 must be able to tell the two apart.
- **D3, title validation at load checks secrets, PII, advice, repo terms, plus private terms and forbidden raw literals when the caller passes them.** Reason: a title holding a private term would otherwise fail at every card, which is what the brief forbids, so the load verdict and the gate verdict must be the same verdict. Detail: the loader calls both `text_check_codes(title, private_terms=private_terms, forbidden_raw_literals=forbidden_raw_literals)` and `action_targets_repo(title)` from `gate.py` (D1). `text_check_codes` covers secrets, PII, advice, and private terms and raw literals when passed, and never returns `L1_ACTION_TARGETS_REPO`: it returns secret patterns, email and phone, the advice list (D9), plus `L1_PRIVATE_TERM` and `L1_RAW_VALUE` arms when terms or literals are supplied. `_l1_text_checks` calls `text_check_codes` per text, and the gate calls `action_targets_repo` on action text only, so load time and gate time verdicts cannot drift. Callers that know the private terms pass them in. Callers that pass nothing get the context free arms, and a title that only fails on a private term then still fails at gate time on the action that carries it. Number backing is not checked at load: it applies to claim text only (gate.py line 414 iterates claims), never to action text. A title with digits and a direction word therefore loads and passes as an action, pinned by the unit test in the test lists below (`Stop the synthetic screens down by 00:00` built in a tmp file).
- **D4, `tag` is required exactly when `evidence == "calendar_tag"`, and must be absent otherwise; `tag` must fullmatch `iki-[a-z]+`.** `tag: NonEmptyStr | None = None` with a model validator: `calendar_tag` without a tag fails validation; any other evidence kind carrying a tag also fails. Reason: a stray tag on a `tap` commitment is data nobody consumes, and strict by default rejects it rather than ignoring it. Further validators on `Commitment`: a `title` that is blank after strip is rejected, because it would collapse to an empty string and match a blank action text. `tag`, when present, must fullmatch `iki-[a-z]+`, the collector `TAG_PATTERN` at [framework/collectors/calendar_ics.py:30](../../framework/collectors/calendar_ics.py), because any other tag can never be observed. ## Risks

- **Fixture churn is the blast radius.** The label rule touches every claim that cites a metric, and the unconditional spelled number rule touches every claim text. A fixture wording that was inert in T8 can newly fire. Mitigated by D15 migration table, the step 4 audit of every text against the advice, direction, period and token rules, and the meta-eval exact code assertions. The implementer should expect wording fixes, and must never fix a failure by editing an expected code.
- **Direction words in ordinary prose.** `more`, `less`, `up`, `down` are common English. A labelled claim that says `more` over a falling period pair now fails, and a one ref claim that says `rose` fails under D14 arm (5). That is the brief strict by default intent. G16 pins the escape (write no direction word). Briefing authors in T11 will feel it first, and T11 has one retry. The pinned lists are closed, so relief is a plan amendment, not a gate tweak. Note `wind-down` with a hyphen is ordinary vocabulary for the Disconnect profile and is not a direction word under the hyphen rule. `wind down` with a space is.
- **Period words in ordinary prose.** Outside `since_last`, a metric claim that says "prior to" or "the last push" while citing the window total is rejected under D14 arm (4). Accepted cost, stated here so T11 authors see it. The escape is to cite the period metric or drop the period word.
- **The label function is specified, not verified against T9.** T9 is in flight on another branch and its producer is not in this tree. If it emits an id spelling this plan does not cover (a `period.<name>` outside `earlier`, `prior`, `last`, or an empty category segment), those claims fail `L1B_METRIC_LABEL_UNKNOWN` closed. That is the designed failure mode, and the D12 table is the single place to amend when T9 lands. A dot inside a category (for example `Node.js`) is covered and is not a risk.
- **Compound spelled numbers back per word.** `ten thousand steps` yields 10 and 1000, so a single ref cannot back it, and `eight and a half hours` backs as 8, and `twenty-one pages` backs as 20, because `one` is not a token there. Accepted and disclosed in the D16 header. Later tickets tell the model to write digits taken from metrics, which removes the path.
- **Example commitments are synthetic by design.** The real file lives outside the repo and is never opened in this ticket. If its real titles contain an advice word or a `calendar_tag` without a tag, the loader rejects the whole file. With D2 that now presents as `L1_COMMITMENTS_UNAVAILABLE` with a reason in the loader result, not as every action reading uncommitted. The operator remedy is to fix the file. The loader silence on path and content is the privacy requirement, not an oversight.
- **`make demo` stays a placeholder in this ticket.** D19 records the position: the example file is proven through loader tests, and `make demo` is wired by the PREREG ticket, not T12. If the reviewer wants demo wiring here, that is new scope to approve on its own, not an implementer improvisation.
