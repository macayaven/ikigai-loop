## Goal

Ticket 10c, `since_last` wording. On Nov 2 the 15:30 live card's Builder side carried a `since_last` claim, "Prs rose by 3 in the last period.", citing the delta of `period.last.prs` as 3. Pull requests in the last period were 24 on the previous card and 27 on this one, so 3 is the change since the last card. In this system's own vocabulary "in the last period" places the change inside the last period, where pull requests went from 2 in the prior period to 27, so the sentence reads as false. The gate passed it. This ticket closes that one wording hole, teaches the replacement phrase in the Wonder prompt in the same change, adds a PREREG deviation, and schedules (does not run) the reviewer's pre-merge evidence. This plan session writes this plan and nothing else: no code, no tests, no fixtures, no commit.

## Approach

### Key decisions (binding on the implementer; each with its reason)

- **D1, accepted phrasings: exactly three, matched as token sequences on the normalised casefolded copy.** Accepted: `since the last card`, `since my last card`, `since the previous card`. Matching: take `normalize_text(text).casefold()` (the copy every rule already uses, [claim_text.py:3067](../../framework/briefing/claim_text.py:3067)), split it into word tokens, and require the phrase's tokens to appear consecutively. Case, extra whitespace, punctuation and hyphen variants therefore cannot change the verdict, and a phrase split across a clause boundary still counts only when its tokens are consecutive, which is the wording a reader sees. No other `since … card` form is accepted: not `since his last card` (the prompt's own section description at [prompt.py:214](../../framework/proposal/prompt.py:214) is prose about the section, not claim wording), not `since the parent briefing` (the briefing-case fixture wording at [evals/briefing_cases.py:318](../../evals/briefing_cases.py:318), which keeps passing only where it already passes; see D5), and not possessive or named-card forms. Reason: a closed list is what lets the prompt teach exactly what the gate accepts (D6), and token-sequence matching reuses the gate's existing normalisation instead of inventing a second one. Note, checked against the code: two of the three already satisfy the period requirement today, because the `last card` substitution at [gate.py:785](../../framework/briefing/gate.py:785) fires inside `since the last card` and `since my last card`; only `since the previous card` is new counting (D5). All three are still pinned as accepted, so the taught set and the accepted set are one list in one place.

- **D2, rejected phrasings: a closed token-pattern set built from the code's period vocabulary.** On the same token stream as D1, reject when any of these patterns occurs, for each `P` in `earlier`, `prior`, `last` (the whole of `PERIOD_WORDS`, [claim_text.py:340](../../framework/briefing/claim_text.py:340), so the other periods' words are covered, not only `last`):
  - `in [the] P [period]`, `during [the] P [period]`, `for [the] P [period]` — `in the last period` and bare `in last` are the brief's first two shapes; `for` is included because the code's own value-period rule already reads `in`, `during`, `for` as the period prepositions ([claim_text.py:2724](../../framework/briefing/claim_text.py:2724)), so `rose by 3 for the last period` places the change the same way.
  - `over [the] P [period]`, `across [the] P [period]` — the brief's `over or across a period` with the period named.
  - `in a period`, `during a period`, `over a period`, `across a period`, and the same four with `the period` — the brief's generic shape with no period named; it still places the change inside some period, which a since-last-card delta never is.
  Deliberately not in the set: a bare period adjective or noun with no containment preposition (`Last prs rose by 3 since the last card.`), because it names which metric changed rather than placing the change inside the period, and stored true drafts use that shape (see Limits); `from P to P` frames and `through`, `within`, `between` phrasings, which the brief does not name and the period rules do not use as containment prepositions — they stay governed by the existing checks and are named in Limits. Checked against the code: hyphenated adjectives (`last-period`, `prior-period`, `earlier-period`) are not bare adjectives — `remove_period_phrases` blanks every hyphen compound before counting ([claim_text.py:1459](../../framework/briefing/claim_text.py:1459)), so a hyphenated period adjective names no period at all. That is existing behaviour this ticket leaves alone, and it is named in Limits. Reason: the set is every containment-preposition pattern the code's period vocabulary supports, pinned as data (one tuple of patterns in `claim_text.py`, one test row per pattern per period word where the shape allows it), so a reviewer can diff the list against this decision.

- **D3, both an accepted and a rejected phrase: rejected.** The new code fires whenever a D2 pattern occurs, even when a D1 phrase is also present, and no other verdict is suppressed or added because of the combination. Reason: "Prs rose by 3 in the last period since the last card." still asserts the inside-period reading; the true clause does not cure the false one, and a rule that accepted the combination would hand the model the cheapest workaround — append the accepted phrase to the wording that already passes. The period requirement (D5) is still evaluated as today, so the combined claim carries the new code alone when its delta, label and sign are right.

## Limits

- A sentence naming the right metric, period and direction that is false in its other words stays out of scope, as [docs/PREREG.md](../PREREG.md) already states for the gate as a whole: this rule reads only the D2 containment patterns, the label, the period, the direction and the delta.
- Anything outside `since_last` is out of scope (D4), including the same containment wording in `working`, where it is usually true.
- What this rule cannot catch, stated plainly: containment wording outside the pinned list (`through the last period`, `within the last period`, `between periods`, a `from prior to last` frame on a single-delta claim, novel prepositions, and bare period adjectives that imply the inside-period reading without stating it); a `since_last` claim that uses an accepted phrase while its other words still misdescribe the change (for example naming the current value as if it were the delta — the delta check catches the digit, not the prose around a backed digit); fact-only `since_last` claims whose facts are true but whose framing misleads; and miswording in a language or spelling that normalisation folds to none of the pinned patterns. Each is a candidate for a later ticket only if the D11 replay shows it occurring.
- A hyphenated period adjective (`last-period`, `prior-period`, `earlier-period`) names no period at all: the period scan blanks every hyphen compound before counting, so such a claim fails the period requirement on its own wording. Checked against the code and deliberately left alone by this ticket.
- D3 rejects a claim that names the metric with a period phrase and states the change since the last card — for example "pushes in the last period rose by 1 since the last card". That reads as true and is rejected anyway. Named here as a false rejection I accept, because the prompt teaches the label-first form and the rule stays simple.
